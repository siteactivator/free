# metrika-export — отчёты Метрики в Excel через API

API Метрики живёт отдельно от интерфейса metrika.yandex.ru: когда интерфейс не
открывается, данные забираются напрямую. Установка с нуля — `README.md`.

## Команды

Из папки скилла:

```powershell
python run.py counters                                   # счётчики, доступные токену → data\counters.xlsx
python run.py report <номер или сайт> [--days 30 | --from ГГГГ-ММ-ДД --to ГГГГ-ММ-ДД]
                     [--group day|week|month] [--only sources,phrases,...] [--top 10000] [--no-compare]
                     [--no-charts]
python run.py raw <номер или сайт> --metrics ym:s:visits,... [--dimensions ...] [--sort -ym:s:visits]
python run.py direct <номер или сайт> [те же --days/--from/--to/--group/--no-compare/--no-charts] [--only ...] [--login логин]
python run.py seo <номер или сайт> [--days 28 | --from --to] [--only ...] [--no-charts]
python run.py panel [--port 8790] [--data <папка с отчётами>] [--no-browser]   # http://127.0.0.1:8790/
```

`panel` — `panel.py`, локальный сервер на 127.0.0.1. `/` — все счётчики токена с кнопками
«Сформировать SEO-отчёт» и «Сформировать Директ»: кнопка запускает `run.py seo|direct <номер>`
отдельным процессом (не больше двух сразу), прогресс — по строкам «Лист…» в выводе. `/seo/`,
`/direct/` — готовые отчёты (вкладки «Метрика» нет: весь трафик — внутри SEO-отчёта). Отметка «Директ подключён» — фоновая проверка
`/management/v1/clients` пачками по 10, кэш на сутки в `data\_direct_counters.json`. Токен нужен.
Сервер живёт, пока открыт терминал: Claude запускает его в фоне и даёт владельцу адрес.
Шапка панели — `BRAND` в `panel.py` и `logo.png` (встраивается в страницу, интернет не нужен).
`METRIKA_DATA` в окружении подменяет папку `data` — так панель с `--data` получает отчёты к себе.

- Токен — `METRIKA_TOKEN` в `.env` рядом с `run.py`. **Не печатать и не
  пересказывать его**; скрипт читает файл сам.
- Период по умолчанию — 30 дней по вчера; сравнение — с прошлым периодом той же
  длины.
- Файл: `data\<номер>_<сайт>\metrika_<сайт>_<начало>_<конец>.xlsx`, первым
  листом — «Панель» с графиками. Рядом — `dashboard_<сайт>_<начало>_<конец>.html`
  (та же панель, картинки встроены) и папка `charts_<начало>_<конец>` с PNG.
- Отчёт — 20–30 запросов, 20–30 секунд. Лимиты API: 5 000 запросов в сутки,
  200 отчётов за 5 минут на счётчик.

## SEO-отчёт

`seo` — `seo_<сайт>_<начало>_<конец>.xlsx` и `dashboard_seo_….html`, два раздела: «Поиск»
(визиты с `lastsignTrafficSource=='organic'`, пять срезов Pixelplus) и «Весь трафик» (все листы
обычного отчёта, функция `collect_traffic`, она же у `report`). Период по умолчанию — 4 полные
недели по последнее воскресенье против тех же недель год назад (сдвиг 364 дня). Длинный
клик — визит из Яндекса дольше 59 с, норма доли по фразе — от 10–15 %; фразы с разным
регистром склеены. Для пересказа главное — «Страницы, потерявшие визиты из поиска» и
красные полосы длинных кликов. Фраза с десятками визитов и 0 % длинных — визиты по 0–2 с:
незамеченные боты или ответ в сниппете.

## Сравнение и роботность

- `--compare yoy|mom|qoq` (у `report`, `seo`, `direct`): год к году — полные недели против тех
  же недель год назад; месяц к месяцу и квартал к кварталу — последний полный против
  предыдущего (`pick_periods`). На странице отчёта те же кнопки: через панель они запускают
  отчёт с `--compare` и открывают новый.
- Все запросы `ym:s` и `ym:pv` — только люди (`isRobot=='No'` добавляется в фильтр в
  `_stat_pages`); у расходов Директа (`ym:ad`) роботности нет. `--with-robots` — все визиты.
  Роботы — до 15–20 % визитов (проверено 12.10.2026: 16,6 % за неделю на живом счётчике).
- Названия листов — без `: \ / ? * [ ]`: Excel их не принимает, отчёт падает целиком.

## Отчёт по Директу

`direct` — отдельный Excel `direct_<сайт>_<начало>_<конец>.xlsx` и панель `dashboard_direct_….html`.
Визиты и цели — из Метрики (фильтр `lastsignAdvEngine` = `ya_direct` или `ya_undefined`); клики и
расход — из пространства `ym:ad` с параметром `direct_client_logins`. Логины скрипт берёт сам:
`/management/v1/clients?counters=<номер>` — аккаунты Директа, к которым у владельца токена есть
доступ. Пусто — отчёт без расходов, с жёлтой подсказкой; так и сказать владельцу.

- Цена цели на листе «Кампании» — расход ÷ достижения всех целей (цели вовлечённости тоже
  входят); на листе «Цели по кампаниям» — по каждой цели. Для заявок смотреть второй лист.
- Клики и визиты не совпадают — нормально: клики считает Директ, визиты — Метрика по
  последнему значимому переходу. Повторные прямые заходы после рекламы тоже идут Директу,
  поэтому визитов бывает больше кликов (проверено 12.10.2026 на живом счётчике: 44 тыс. визитов на 28 тыс. кликов).
- Запасной путь — UTM: `lastsignUTMCampaign/Content/Term` работают, когда группировки Директа
  отвечают 503 (сбой 12.10.2026). Панель берёт кампании из UTM, если листа «Кампании» нет.
  «Автотаргетинг и фразы» — по `utm_term` (`---autotargeting`); визиты без метки — отдельной строкой.
- Часы, дни недели, пол, возраст, новые — графики «визиты + отклонение конверсии от средней в
  п.п.»: конверсия в любую цель везде 80–90 % из-за целей вовлечённости.
- Расходы склеиваются с визитами по номеру кампании или объявления, у остальных листов —
  по названию. Строки, где были клики, но не было визитов, в таблицу не попадают; итог
  расхода в Сводке — полный, из Директа.

## Как отвечать владельцу

1. **Счётчик.** Если владелец назвал сайт — передать его как есть, скрипт найдёт
   счётчик по адресу. Подходит несколько — показать список и спросить. Не знает
   номер — `python run.py counters`.
2. **Период.** «За сентябрь» — `--from 2026-09-01 --to 2026-09-30`; «за
   квартал» — `--days 90`. Сравнение с прошлым периодом идёт по умолчанию.
3. **Читать Excel** — openpyxl или pandas. Строка «Итого и в среднем» — первая
   строка листа, шапка — вторая. Время на сайте хранится как доля суток (×86400 —
   секунды).
4. **Пересказ:** начать со Сводки — что выросло и упало, в процентах и
   процентных пунктах. Потом причины по листам: какой источник, поисковик,
   страница входа или устройство дали изменение. Для сравнения по листам —
   выгрузить прошлый период отдельным отчётом. В конце дать полный путь к
   `dashboard_….html`: владельцу проще открыть его, чем Excel. Картинки из
   `charts_…` можно открыть и посмотреть самому, прежде чем пересказывать.
5. **Честно о данных:**
   - лист «выборка N %» в Сводке — цифры приблизительные, так и сказать;
   - «Строк в файле» меньше «Всего в Метрике» — лист обрезан `--top`;
   - итог на листе с группировкой считается только по строкам с определённым
     значением — сумма по городам меньше всех визитов;
   - поисковые фразы поисковики в основном скрывают — по ним нельзя судить о
     всём поисковом трафике;
   - «Данные за … похоже, неполные» в выводе — последний день меньше трети
     медианы. Это недосчёт Метрики, а не обвал трафика: так и сказать и
     предложить перевыгрузить отчёт позже.

## Неочевидное

- **«Запрос слишком сложный» (400)** при перегрузке API — временное. Скрипт
  повторяет дважды с паузой, потом берёт выборку 50 % и 10 % и помечает лист.
  Проверено 12.10.2026: шесть отчётов по источникам упали с этой ошибкой и
  через минуту прошли полностью.
- Источник — последний значимый (`lastsign…`), как в интерфейсе по умолчанию.
- «Цели по источникам» — 9 целей на запрос (визиты + 2 метрики на цель, лимит API — 20
  метрик). Длинная таблица «цель — источник», не матрица: фильтр по цели. На панели —
  тепловая карта, цвет нормирован внутри строки: у целей разный масштаб конверсии.
- Типы целей переведены на русский (`GOAL_TYPES` в `run.py`); неизвестный тип
  остаётся как есть.
- Популярные страницы — из просмотров (`ym:pv:`), остальные листы — из
  визитов (`ym:s:`).
- **Панель** — `charts.py`, собирается из уже выгруженных таблиц; лишний запрос
  один — динамика прошлого периода. Нет seaborn — отчёт собирается без панели,
  ошибка в графиках не роняет Excel.
- Полосы рисуются `matplotlib.barh`, не `seaborn.barplot`: barplot усредняет
  строки с одинаковой подписью, а после сокращения адресов страниц такие бывают.
- Холсты фиксированной ширины (`layout='constrained'`, без `bbox_inches='tight'`):
  длинные подписи ужимают область графика, а не расширяют картинку, и все
  графики панели получаются в одном масштабе.
- Неполный последний день проверяется только при группировке по дням: крайние
  недели и месяцы неполные по календарю, это нормально.
