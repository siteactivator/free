# aparser — рабочие парсеры A-Parser командами

A-Parser работает на сервере в фоне; скилл ставит ему задачи через HTTP API и отдаёт xlsx.
Интерфейс A-Parser не открывать. Подробная инструкция (все команды, колонки, рецепты,
скорость, ограничения, установка с нуля) — `README.md` в папке скилла. Все 137 парсеров — `PARSERS.md`.
Панель задач (экран, проверка методов кнопками, свой скрипт в панели, API) — `PANEL.md`.

Всё лежит в папке скилла: настройки — `.env` (образец `.env.example`), результаты — `data\<команда>\`,
запуски для панели — `data\_runs\`.

Особенности своей установки (где стоит A-Parser, какие заведены чекеры и пресеты, решения пользователя,
проверки на его данных, свои команды `local/cmd_*.py`) — в `local/README.md`, если папка есть; в git она не попадает. Прочитать перед первой
командой. Новые частности писать туда, а не в README и не сюда.

## Перед работой

```powershell
cd <папка скилла>
python run.py status             # жив ли A-Parser, версия, живые прокси, баланс CapMonster
python server.py start           # если не запущен
python run.py <команда> -h       # параметры команды
python run.py parsers            # что работает и какой командой (без A-Parser)
```

Панель задач (http://127.0.0.1:8770/) вручную не запускать: её поднимает любая команда (правило 11).

## Команды

Вход у всех: `-q "а;б;в"` или `-f файл` (txt по строке, xlsx/csv — первая колонка); общие
`--threads` (5; Google и Ahrefs — 100, таблица `THREADS` в `common.py`), `--label`, `--retry` (1) и `--pause` (30 с) — повтор неполученных после паузы.
Выход: `data\<команда>\<дата_время>_<метка>.xlsx` + `.json`. `--engine`/`--store` принимают список через запятую или `all`.

## Правила

1. **Через скилл, не через интерфейс.** Опции — только проверенные: `validate()` сверяет каждое
   имя с A-Parser, опечатка может уронить программу. Капча (`capmonster`) подставляется сама.
2. **«получено = False» — это капча/бан/нет прокси, а не «нет данных»**: перезапустить только
   неполученные, при массовых отказах — `status`. `serp` или `positions` оборвались посреди
   прогона — запустить ту же команду с тем же `--label`: готовые порции возьмутся из кэша.
3. **Не запускать несколько тяжёлых команд одновременно**: браузерные парсеры (Яндекс, Google,
   Рамблер, YouTube, AI Mode) под нагрузкой замедляются в разы. Исключение — большой список Google:
   две команды по половине, вторая через минуту после первой (README, `serp`); больше двух — нет.
4. **Считать расходы** на больших прогонах: 10–20 запросов, потом трафик прокси (кабинет) и
   баланс капчи (`status`) × объём. Google — пачкой: по умолчанию 100 потоков, больше не ставить
   (README, `serp`), пробу тоже пачкой, а не поодиночке. `--paa` у Google — только по явной
   просьбе пользователя: на каждый вопрос A-Parser делает отдельный запрос за ответом.
5. **Выдача страны — через прокси этой страны.** `serp` и `positions` берут проксичекер
   `APARSER_COUNTRY_CHECKER` для `--country` (по умолчанию `--gl`, то есть `ru`). Выдачу другой
   страны задавать целиком: США — `--gl us --hl en --google-domain www.google.com`, Индия —
   `--gl in --hl en --google-domain www.google.co.in`, Беларусь — `--gl by --google-domain www.google.by`
   (Яндекс: `--lr 157 --country by`). Какие чекеры заведены — `local/README.md`. Для другой страны команда
   предупредит и пойдёт через мировые прокси, а Google с чужих IP почти не отвечает: предложить
   пользователю завести чекер в интерфейсе A-Parser (README, «Прокси по стране выдачи»), сам скилл
   их не создаёт. Всё о поставщике прокси (как задать страну, формат строк, ловушки, замеры) — в
   его профиле `proxies/<APARSER_PROXY_PROFILE>.md`, путь печатает `status`. Яндекс — только `engine=browser`, 27.09.2026 до 6–7 мин на запрос.
6. **Wordstat — не здесь**: частотности — официальный API Wordstat. Нерабочие и требующие
   аккаунтов парсеры — заготовки `stub`: предупреждать пользователя, что метод не проверен, и
   разбирать с `--debug` (README, «Заготовки: разбирайтесь сами»).
7. **Персональные данные посторонних не выгружать**: авторы комментариев, подписчики, email.
8. **Доступы не печатать**: значения из `.env` не выводить (куки и токены — только через `.env`, не в команде); поле
   `proxy` из результатов вырезается.
9. Новая команда — по README, «Как добавить команду»; обновить `catalog.py`, README и этот файл.
10. **`check` — только по просьбе пользователя.** Не запускать самому: ни перед командами, ни после
    правок, ни «для проверки». Состояние методов смотреть в реестре панели (итог последней проверки).
    Пользователь проверяет методы сам — кнопками в панели задач (метод / группа, очередь); просят
    проверить конкретные методы — `check --only <id>`, а не всю проверку.
11. **Ссылка на панель задач — в чат при каждом запуске команды, без просьбы.** Команда (кроме `status`,
    `parsers`, списка `stub`) сама поднимает панель фоновым процессом и первой строкой печатает
    `Панель задач: http://127.0.0.1:8770/`. В том же сообщении, где говоришь пользователю о запуске, дай
    кликабельную markdown-ссылку `[Панель задач](http://127.0.0.1:8770/)` — там ход команды и готовые xlsx.
    Для фоновых команд (`run_in_background`) — сразу при запуске, не дожидаясь вывода: адрес всегда этот.
    `panel.py` самому не запускать и не останавливать. Команда написала «Панель задач не поднялась» — сказать
    пользователю и показать хвост `data\_panel.log`; команда при этом работает.

**Отчёт:** в `.json` — весь ответ, кроме доступов прокси, тела страниц/заголовков, служебного и данных
посторонних людей; в `.xlsx` — основные листы + лист «прочие поля» со всем непустым, что команда не вывела
(`ap.Result` помнит прочитанные поля, `common.extras()`). Полезное с этого листа — выводить в основную таблицу.

## Грабли (проверено 27.09.2026)

- **Индексация Google — только `index --engine google`, не `serp` с `site:<url>`**: `serp` отдаёт пустую выдачу и на
  заведомо проиндексированные страницы (6 из 15). Выводов «не в индексе» из него не делать.
- **`index --engine google`: «да» надёжно, «нет» на чужих страницах — нет.** Свои страницы с показами в Search Console
  он находит все (15 из 15), а на статьях-донорах у половины ответов «нет» домен донора есть в Search Console среди
  ссылающихся (52 из 101); «да» подтвердилось у 56 из 60. «Нет» доводом не считать и доноров по нему не отсеивать;
  размещение принимать по Search Console, «Ссылки» (домен в «Сайты, ссылающиеся чаще всего» или URL в «Последние
  ссылки»). Контроль на своих страницах чужие не проверяет. Главные и разделы — «пусто» (README, `index`).
- **Выдача `serp --engine google` может не совпадать с браузерной**: на 4 запросах по США с браузером без входа в
  аккаунт совпали 2 страницы из 34, первого в браузере сайта в выдаче не было, а повторный сбор совпадал на 85 %.
  Расхождение живой выдачи с парсерной (плюс персонализация) — известное и принятое. **Решение пользователя
  10.11.2026:** для анализа запросов и кластеризации опираться на `serp` A-Parser. Он ближе к реальному
  пользователю, чем XMLRiver и ТОП Ahrefs, и снимает не XML-выдачу. Анализ из-за расхождения с браузером не
  останавливать.
- **Пустая органика при «успехе» — сбой**: Яндекс 27.09 отдал страницу с 2 объявлениями без выдачи, A-Parser
  засчитал успех. `serp`/`positions` переспрашивают такие запросы раз и иначе ставят «не получено».
- **Массовое «не получено» + `SOCKS5 error: Auth failed` в логе** — кончился трафик или подписка прокси,
  а не сломались парсеры; `status` при выключенной проверке прокси всё равно показывает тысячи живых.
- **Google SafeBrowsing через A-Parser** — общий ключ A-Parser, квота кончается (429). С
  `GOOGLE_SAFEBROWSING_KEY` в `.env` проверка `safe_google` идёт в Safe Browsing API напрямую своим ключом.
- OpenAI: ключ `OPENAI_API_KEY` в `.env`, `api_key` + `another_model` в опциях `OpenAI::ChatGPT`;
  у gpt-5 в `max_tokens` входят рассуждения. `raw --parser OpenAI::*` подставляет ключ сам — не писать его в команде.
- Keys.so в A-Parser — кука `userlogin` из браузера (токен API Keys.so не подходит); Вордкрафт — логин/пароль
  Яндекса в `accounts.txt`, ключ Search API Яндекса не подходит.
- `SE::Bing` не работает — выдача Bing берётся из `SE::Bing::Position` (запрос «домен фраза»,
  подставляется example.com); с `region=ru-RU` он ломается.
- `SE::Google::Trends` с `search_region` ломается — только мир; период по умолчанию `today+5-y`.
- `SE::Google` с опцией `location` ломается; по умолчанию листает 5 страниц — всегда задавать `pagecount`.
- Парсеры позиций A-Parser ищут точный хост (`www.site.ru` ≠ `site.ru`); скилл считает позиции по
  выдаче сам и засчитывает поддомены.
- `Telegram::GroupScraper` через API отдаёт один пост на запрос — номер последнего поста берётся
  со страницы `t.me/s/<канал>`; `checkPostsCount=1`, чтобы не перебирать пустые номера.
- `Browser::ScreenshotsMaker` отдаёт PNG строкой — в байты через `latin-1`.
- `SE::Yandex::ByImage` не берёт PNG-миниатюры — нужен прямой адрес JPG.
- Переводчикам нужен язык: Google и DeepL — `to_language`, Bing — `to`.
- Нули (`exists`, `compromised`, KD) — это ответ «нет/чисто/легко», а не ошибка.
- `Net::HTTP` считает успехом любой код; для повторов на 429/5xx — `goodCode` (один код) или
  `goodCodeRegex` для нескольких.
