# A-Parser без интерфейса: скилл aparser

A-Parser — программа для SEO-парсинга, внутри больше 130 парсеров: выдача и подсказки
поисковиков, Whois, веб-архив, Ahrefs, MOZ, Majestic и многое другое. Возможностей много, но
интерфейс перегружен: чтобы снять позиции, нужно собрать задание из десятка настроек.

Скилл убирает эту возню. Задача ставится одной командой в терминале, результат приходит
таблицей Excel. С Claude Code даже команду писать не нужно: «сними позиции site.ru в Москве по
запросам из queries.txt, ТОП-30».

Внутри **43 команды**. Они покрывают **86 парсеров**, которые заработали у нас на A-Parser
1.2.3656 27.09.2026, и ещё **37 заготовок** для остальных — метод добавлен, но в работе не
проверен, разбирайтесь сами. Плюс **панель задач** в браузере: что сейчас идёт, сколько
сделано, сколько осталось.

Что умеет:

- выдача и позиции в Яндексе, Google, Bing, DuckDuckGo, Yahoo, AOL, Рамблере, Seznam и You;
- подсказки из 7 источников, фразы и частотности Букварикса, идеи и сложность Ahrefs, Google
  Trends, объявления Яндекс Директа;
- сводная проверка доменов по 19 параметрам: Whois, архив, РКН, ИКС, Ahrefs DR и трафик, MOZ DA и
  Spam Score, Majestic TF/CF, Mustat, чёрные списки Google и Яндекса, взлом, DNS, хостинг;
- доноры и битые ссылки по Ahrefs и **ASpamRank** — доля доноров-линкферм;
- проверка, стоит ли купленная ссылка на странице-доноре;
- статья, текст, ссылки и язык со страницы, скриншоты, переводы, орфография, правка текста;
- ответы нейросетей (Google AI Mode, OpenAI, Duck.ai, DeepAI) и упоминается ли в них ваш сайт;
- картинки и видео, YouTube с расшифровкой, Reddit, TikTok, Telegram, приложения, товары, карты.

> **Нужна лицензия A-Parser Enterprise.** Управлять A-Parser через API можно только в ней. На
> лицензиях Lite и Pro скилл работать не будет. Купить —
> [a-parser.com](https://a-parser.com/?ref=21157) (реферальная ссылка автора курса).

Скилл собран и проверен 26–27.09.2026 на A-Parser 1.2.3390 и 1.2.3656.

## Как это работает

```
 run.py (скилл)  ──запрос по API──►  A-Parser на вашем компьютере
                 127.0.0.1:9091/API         │
                                            ├─► прокси (свой IP на каждый запрос)
                                            ├─► сервис капчи CapMonster
                                            └─► Яндекс, Google, Ahrefs, Whois, веб-архив, сайты …
        ◄─────────── ответ с данными ───────┘
   → таблица Excel в папке data\ скилла           → состояние запуска — в панели задач (panel.py)
```

- A-Parser работает в фоне как обычная программа. Прокси, капча и встроенный браузер
  настраиваются внутри него один раз.
- Скилл сам ничего не парсит: отправляет A-Parser пачку запросов, ждёт ответ и раскладывает его
  по листам Excel с русскими названиями колонок.
- Капча подключается автоматически: если парсеру нужна капча, скилл сам ставит ему ваш пресет.
- Перед отправкой скилл сверяет имена настроек с A-Parser: опечатка в настройке может уронить
  программу целиком.
- Из результатов вырезаются логин и пароль прокси, сырые HTML-страницы и персональные данные
  посторонних людей (авторы комментариев, подписчики, email).
- Каждый запуск пишет своё состояние для панели задач — её можно открыть в браузере и смотреть,
  как идёт долгая команда.

## Шаг 1. Лицензия и IP-адрес

1. Купите лицензию **Enterprise** на [a-parser.com](https://a-parser.com/?ref=21157)
   (реферальная ссылка автора курса). После
   покупки кабинет попросит включить двухфакторную аутентификацию: без неё
   дальше не пустит, и отключить её потом нельзя.
2. Узнайте внешний IP компьютера, на который ставите A-Parser:

   ```powershell
   Invoke-RestMethod https://api.ipify.org
   ```

3. В [личном кабинете](https://a-parser.com/pages/members-area): **A-Parser →
   Настройка IP** — впишите этот IP и сохраните. A-Parser запускается только на
   компьютере с этим IP.

**Если IP меняется** (обычный домашний интернет): после каждой смены IP его нужно
заново вписывать в кабинете, иначе A-Parser не запустится. Менять IP в кабинете
можно не чаще нескольких раз в сутки. Для постоянной работы удобнее
статический IP у провайдера или арендованный сервер.

## Шаг 2. Установка A-Parser и защита от доступа извне

1. В кабинете: **A-Parser → Загрузки**. Сначала нажмите **Обновить**: кабинет
   соберёт архив последней версии под вашу лицензию, это около минуты. Окно может
   показать «Ошибка обновления», хотя версия при этом сменилась: смотрите на поле
   «Текущая версия». Затем скачайте архив для Windows x64.
2. Распакуйте архив в `C:\A-parser`. Путь лучше выбрать **без кириллицы и
   пробелов**. Внутри должны лежать `aparser.exe` и, в новых версиях, ещё
   `aparser-core.exe`.
3. **Закройте доступ извне до первого запуска.** Сразу после установки A-Parser
   принимает подключения на порту 9091 со всех адресов, а пароль у него пустой.
   На сервере с публичным IP в интерфейс сможет зайти кто угодно из интернета и
   пользоваться парсером и вашими прокси, на домашнем компьютере — любой в вашей
   сети. Одна строка в настройках оставляет доступ только с этого компьютера:

   ```powershell
   New-Item -ItemType Directory -Force C:\A-parser\config
   Set-Content -Path C:\A-parser\config\config.txt -Value "bind: 127.0.0.1:9091" -Encoding ascii
   ```

   Если A-Parser уже запускался, перезапустите его: `config.txt` читается только
   при старте.

## Шаг 3. Первый запуск

1. Запустите `C:\A-parser\aparser.exe` двойным кликом. Если окно закрывается само
   через несколько секунд (так бывает на Windows Server), запускайте
   `aparser-core.exe`. Скилл потом сам выбирает `aparser-core.exe`, если он есть.
2. Первый запуск долгий, от 30 секунд до нескольких минут: программа докачивает
   компоненты.
3. Откройте в браузере на этом компьютере [http://127.0.0.1:9091/](http://127.0.0.1:9091/)
   и нажмите **Login**, пароль пустой. Откроется интерфейс A-Parser. Он нужен
   только на шагах 4 и 5, дальше всё делает скилл.
4. **Пароль, по желанию.** Интерфейс → Настройки → Общие настройки → Пароль. Этот
   же пароль действует для API, поэтому его нужно вписать в `.env` на шаге 7. Если
   доступ закрыт строкой `bind` из шага 2, пароль можно не ставить. Если пароль
   забыт, запустите A-Parser один раз с ключом `-resetpassword`.

## Шаг 4. Прокси

Без прокси Яндекс быстро начинает отвечать капчей, Ahrefs и другие сервисы
ограничивают число запросов с одного IP. Whois, DNS и подсказки менее
требовательны, но через прокси надёжнее и они.

Прокси подключаются в A-Parser через **проксичекер**: это список прокси с
настройками. Через API прокси не настраиваются, поэтому шаг делается один раз в
интерфейсе.

### Вариант А. Бонусные прокси Unlimited: первый месяц с лицензией

С лицензией Enterprise идут прокси Unlimited на 50 потоков на месяц. Доступ к ним
по вашему IP, без логина и пароля.

1. Кабинет → вкладка **Прокси** → **Использовать IP** → **Сохранить**.
2. В A-Parser: **Настройки → Настройки проксичекера**. Поставьте галочку **Не
   проверять прокси**, остальное оставьте как есть, нажмите **Добавить новый** и
   введите имя, например `unlimited`.
3. Во вкладке **Проксичекер** проверьте, что новый чекер включён. Его рабочая
   папка — `C:\A-parser\files\proxy\unlimited\`.
4. Создайте в этой папке файл `sites.txt` с одной строкой:

   ```
   http://work.a-poster.info/prx/perm_socks.txt
   ```

   По этой ссылке A-Parser каждые 30 секунд получает свежий список живых прокси.
5. Во вкладке **Проксичекер** у чекера поле «Всего живых» должно стать больше 0.

### Вариант Б. Premium Mix: оплата за трафик

На этих прокси скилл проверяли. Это 10 000 резидентских прокси по всему миру, IP
держится 10 минут. На 26.09.2026 в кабинете был бесплатный пробный пакет 3 ГБ на
3 дня, дальше от $0,95 за ГБ.

1. Кабинет → **Прокси → Premium Mix**. Активируйте пакет и сгенерируйте ссылку на
   список: логин, пароль, тип SOCKS5, ротация Sticky 10 минут, формат
   `login:password@host:port`. Ссылку сохраните у себя.
2. В A-Parser: **Настройки → Настройки проксичекера**, и в настройках:
   - **Тип прокси** — только SOCKS5. Значение по умолчанию «HTTP, SOCKS5» не
     подходит;
   - **Использовать авторизацию прокси** — включить;
   - **Не проверять прокси** — включить: платные прокси проверять незачем,
     проверка только тратит трафик.

   Нажмите **Добавить новый**, имя — `mix`.
3. В папке `C:\A-parser\files\proxy\mix\` создайте файл `sites.txt` и вставьте
   туда ссылку из кабинета. Файл `proxy.txt` рядом оставьте пустым.
4. Во вкладке **Проксичекер** у чекера `mix` «Всего живых» должно стать 10 000.

Когда меняется пакет или пароль прокси, достаточно заменить ссылку в `sites.txt`.
Новый список подхватится после перезапуска A-Parser.

Имя своего проксичекера (`unlimited`, `mix` или другое) впишите потом в `.env`, в
`APARSER_PROXY_CHECKER`: команда `status` будет показывать, сколько в нём живых
прокси.

## Шаг 5. Капча: CapMonster

Яндекс время от времени показывает капчу, а бесплатный чекер Ahrefs закрыт
проверкой Cloudflare Turnstile. Их решает сервис капчи.

1. Зарегистрируйтесь на [capmonster.cloud](https://capmonster.cloud/), пополните
   баланс на несколько долларов и скопируйте ключ API из кабинета.
2. В A-Parser: **Настройки → Настройки парсеров**. Выберите парсер
   **Util::AntiGate**, нажмите **Добавить новый** и введите имя `capmonster`. В
   поле **Provider** выберите **CapMonster cloud**: в списке он записан именно
   так, через пробел. В **Client key** вставьте ключ. Сохраните.
3. То же самое для **Util::ReCaptcha2** и **Util::Turnstile**. Без Turnstile не
   работает команда `ahrefs`.

Имя `capmonster` скилл подставляет сам. Если назвали пресеты иначе или пользуетесь
другим сервисом капчи из списка Provider, впишите своё имя в `.env`, в
`APARSER_CAPTCHA_PRESET`. Баланс `status` показывает только для CapMonster.

## Шаг 6. Python и папка скилла

### Python

1. Откройте [python.org/downloads](https://www.python.org/downloads/) и скачайте
   Python 3.10 или новее.
2. На первом экране установщика поставьте галочку **Add python.exe to PATH** внизу
   окна. Без неё команда `python` не будет работать.
3. Нажмите **Install Now**, дождитесь окончания и **откройте PowerShell заново**.

Другой способ — одной командой:

```powershell
winget install -e --id Python.Python.3.12
```

Проверка: `python --version` должна показать `Python 3.10` или новее. Если вместо
версии открылся Microsoft Store, откройте **Параметры → Приложения →
Дополнительные параметры приложений → Псевдонимы выполнения приложений** и
выключите `python.exe` и `python3.exe`.

### Папка скилла

1. Скопируйте папку `aparser` в `C:\aparser` или в другое место без кириллицы и
   пробелов в пути. В ней лежат:

   | Файл | Что это |
   |---|---|
   | `run.py` | все команды: `python run.py <команда> …` |
   | `cmd_search.py`, `cmd_keywords.py`, `cmd_domains.py`, `cmd_content.py`, `cmd_more.py` | команды по разделам |
   | `cmd_stubs.py` | заготовки для 37 непроверенных парсеров |
   | `common.py` | ввод запросов, запуск парсера, сохранение Excel |
   | `aparser.py` | связь с API A-Parser: запросы, проверка настроек, разбор ответа |
   | `donors.py` | правило ASpamRank: какие доноры похожи на линкфермы |
   | `catalog.py` | итоги проверки всех 137 парсеров и какой командой каждый вызывается |
   | `server.py` | запуск, остановка и проверка A-Parser, просмотр его лога |
   | `progress.py`, `panel.py`, `panel.html` | панель задач |
   | `cmd_check.py` | проверка методов (`python run.py check`) — итоги для панели |
   | `SKILL.md` | инструкция для Claude Code |
   | `PARSERS.md` | все 137 парсеров: что работает, что нет, чем вызывается |
   | `PANEL.md` | подробное руководство по панели задач |
   | `README.md` | этот файл |
   | `requirements.txt` | список библиотек Python |
   | `.env.example` | образец файла настроек |
   | `.gitignore` | чтобы пароли и результаты не попали в git |

2. Откройте терминал в этой папке и поставьте библиотеки:

   ```powershell
   cd C:\aparser
   python -m pip install -r requirements.txt
   ```

   В конце должно быть `Successfully installed …` или
   `Requirement already satisfied`.

## Шаг 7. Файл настроек .env

```powershell
Copy-Item .env.example .env
notepad .env
```

В Блокноте поправьте значения после знака `=`:

| Настройка | Что вписать |

## Общее для всех команд

**Вход** — одним из двух способов или обоими сразу:

- `-q "первый;второй;третий"` — запросы, адреса, домены через точку с запятой;
- `-f путь` — `.txt` (по значению на строку) или `.xlsx`/`.csv` (берётся первая колонка,
  заголовок пропускается).

Повторы убираются, порядок сохраняется. Для доменов протокол, `www.` и путь отбрасываются
автоматически: можно давать и `site.ru`, и `https://www.site.ru/page`.

**Общие параметры:**

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--threads N` | 5 | сколько запросов A-Parser выполняет параллельно |
| `--label текст` | по запросу или по источнику | метка в имени файла |
| `--retry N` | 1 (у `stub` — 0) | сколько раз переспросить неполученные запросы |
| `--pause S` | 30 | пауза перед повтором, секунд |

**Несколько источников сразу.** У `serp`, `positions`, `suggest`, `images`, `video`,
`translate`, `ai`, `apps`, `shop`, `maps` параметр `--engine` (или `--store`) принимает
список через запятую или `all`. Результаты всех источников ложатся в одну таблицу с колонкой
«поисковик» / «источник».

**Выход** — два файла:

```
data\<команда>\<ГГГГ-ММ-ДД_ЧЧММ>_<метка>.xlsx   ← таблицы
data\<команда>\<ГГГГ-ММ-ДД_ЧЧММ>_<метка>.json   ← сырой ответ A-Parser
```

- Первая строка каждого листа закреплена, ширина колонок подобрана.
- Пустые листы (кроме первого) не создаются: нет рекламы — нет листа «реклама».
- В ячейке Excel не больше 32 767 символов. Длиннее (текст статьи, расшифровка видео)
  обрезается с пометкой «обрезано, целиком — в .json».
- Числа сохраняются числами, чтобы по ним можно было сортировать.

**Колонка «получено».** `False` значит, что A-Parser не справился после всех попыток:
капча, блокировка, кончились прокси. Это **не** «нет данных». Такие запросы команда
перечисляет в конце:

```
  НЕ получено (2): ['окна пвх', 'остекление балкона'] — перезапустите их отдельно
```

**Повторы с паузой.** A-Parser сам делает до 10 попыток на запрос, но подряд, без пауз — короткий сбой
(капча, лимит сервиса) их съедает. Поэтому скилл переспрашивает неполученные запросы ещё раз после
паузы: `--retry N` (по умолчанию 1), `--pause S` (по умолчанию 30 секунд). В выводе это строка
`Rank::Ahrefs: не получено 2 — повтор 1/1 через 30 с`. У заготовок (`stub`) повтор по умолчанию
выключен — включается `--retry 1`. Если после повтора всё равно `False` у всех подряд — смотрите
прокси (`python run.py status`): чаще всего кончился трафик или подписка.

**Что попадает в отчёт.** Скилл берёт у A-Parser полный ответ парсера (`rawResults`). В `.json` уходит всё,
кроме доступов прокси, тела страниц и HTTP-заголовков (`data`, `headers`, `pages` — кроме команд, которым
они нужны), служебной статистики запроса и персональных данных посторонних (комментарии YouTube и Reddit
с авторами, подписчики TikTok — вырезаются до записи). В `.xlsx` команда раскладывает нужные поля по
листам, а **всё непустое, что она не вывела, — на лист «прочие поля»** (запрос · поле · значение; поле
списка — `список[№].поле`). Так ничего из ответа не теряется молча, в том числе новые поля после
обновления A-Parser: увидели на этом листе полезное — выведите его в основную таблицу (раздел «Как
добавить команду»). На лист не идут картинки и превью, служебные id и ссылки на кэш, данные людей
(авторы, ники, email, подписчики). Лимиты источника скилл не обходит: MOZ отдаёт по 7 записей в
списках, Ahrefs — 20 доноров.

**Прогресс.** Большие списки режутся на порции по 50 запросов, после каждой печатается строка:

```
  SE::Yandex: 50/300 (успешно 50/50, 212 с)
```

### `serp` — выдача поисковиков

```powershell
python run.py serp -q "купить пластиковые окна;окна пвх цена" --engine yandex --lr 213
```

| `--engine` | Парсер A-Parser | Регион и язык | Заметки |
|---|---|---|---|
| `yandex` (по умолчанию) | `SE::Yandex`, `engine=browser` | `--lr` (213 — Москва) | только через браузер; капча — CapMonster; до 20 попыток |
| `google` | `SE::Google` | `--gl ru --hl ru --google-domain www.google.ru`, язык `lang_ru` | русская выдача без привязки к городу: регион Google берёт по IP прокси (см. «Ограничения и тонкости») |
| `bing` | `SE::Bing::Position` | по IP прокси, язык — по запросу | обычный `SE::Bing` не работает, берём выдачу из парсера позиций |
| `duckduckgo` | `SE::DuckDuckGo` | регион `ru-ru`, язык `ru_RU` | есть реклама |
| `yahoo` | `SE::Yahoo` | мир | есть реклама |
| `aol` | `SE::AOL` | мир | |
| `rambler` | `SE::Rambler` | Россия | медленный: ~2,5 мин на запрос |
| `seznam` | `SE::Seznam` | Чехия | |
| `you` | `SE::You` | мир | ИИ-ответ часто пустой |

Параметры: `--pages N` — страниц выдачи (по ~10 результатов, по умолчанию 1); `--lr` —
регион Яндекса; `--gl`, `--hl`, `--google-domain` — Google.

**Органика.** Из нумерации исключены ссылки на сам поисковик: колдунщики Яндекса
(«Популярные товары» и другие ссылки на `ya.ru/search`), блок «ещё по запросу» (относительная
ссылка `/search?…`, приходит как `http:///search?…`), ссылки на поиск и карты Google.

**Пустая выдача — это сбой, а не ответ.** 27.09.2026 Яндекс вернул страницу с двумя
объявлениями и без органики, и A-Parser засчитал её как успешную без повторов. Поэтому скилл
переспрашивает запросы с пустой органикой один раз, а если выдача снова пустая, ставит
«получено = False» и пишет запрос в список «НЕ получено». В `positions` такие запросы не
превращаются в «сайта нет в ТОПе».

| Лист | Колонки |
|---|---|
| `выдача` | поисковик, запрос, позиция, url, домен, заголовок, сниппет, дата |
| `сводка` | поисковик, запрос, получено, всего результатов, позиций, исправленный запрос, ИИ-ответ (Google AI Overview, You), определённый регион |
| `реклама` | поисковик, запрос, №, домен, url, заголовок, текст, видимая ссылка |
| `похожие запросы` | поисковик, запрос, похожий запрос |
| `вопросы` | поисковик, запрос, вопрос, ответ, источник, ИИ (Google «Похожие вопросы») |
| `ИИ-источники` | поисковик, запрос, url, заголовок, фрагмент (источники AI Overview Google) |

## Домены и ссылки

### `domains` — сводная проверка доменов

```powershell
python run.py domains -f domains.txt                            # набор по умолчанию
python run.py domains -f drops.txt --checks pbn                 # набор для отбора дропов
python run.py domains -q "site.ru" --checks all                 # всё
python run.py domains -f list.txt --checks whois,ahrefs,moz,majestic
```

Все проверки — в одну таблицу, по строке на домен. Разные проверки идут **параллельно** (до 6
одновременно), внутри проверки — `--threads` доменов сразу.

| Проверка | Парсер | Колонки |
|---|---|---|
| `whois` | `Net::Whois` (RDAP/WHOIS) | зарегистрирован, регистратор, создан, обновлён, оплачен до, освобождается (.ru/.su/.рф), статусы домена (clientHold, redemptionPeriod, pendingDelete… — на каком этапе дроп), NS |
| `archive` | `Rank::Archive` (Wayback Machine) | архив: первый снимок, последний, снимков |
| `rkn` | реестр РКН с antifilter.download (~1,7 млн доменов) | РКН (реестр): 1 — в реестре, 0 — нет |
| `rkn_ap` | `Check::RosKomNadzor` (сайт РКН + капча) | РКН (сайт РКН), основание, дата, орган |
| `sqi` | `SE::Yandex::SQI` | ИКС, рейтинг и отзывы в Яндексе, официальный сайт |
| `dns` | `Net::DNS` | IP; DNS-записи с TTL (тип — опция `query_type` парсера, по умолчанию только A; MX, TXT, NS — через `raw --parser Net::DNS --set query_type=MX`) |
| `hosting` | `Net::DNS` + `IP::Info` | хостинг: компания, ASN, страна, тип |
| `cms` | `Rank::CMS` | CMS |
| `ahrefs` | `Rank::Ahrefs` | Ahrefs DR, беклинков, ссылающихся доменов, доменов dofollow % |
| `traffic` | `Rank::Ahrefs::TrafficChecker` | Ahrefs: трафик в месяц, стоимость трафика $ |
| `moz` | `Rank::MOZ` | MOZ DA, Spam Score %, ссылающихся доменов, ключей |
| `majestic` | `Rank::MajesticSEO` | Majestic TF, CF, беклинков, ссылающихся доменов, URL в индексе |
| `mustat` | `Rank::Mustat` | визитов в день, в неделю, в месяц, в год, стоимость сайта $, рейтинг |
| `safe_google` | Google Safe Browsing API своим ключом (`GOOGLE_SAFEBROWSING_KEY` в .env), без ключа — `SE::Google::SafeBrowsing` | Google SafeBrowsing: 1 — в чёрном списке, 0 — чисто; угрозы (тип) |
| `safe_yandex` | `SE::Yandex::SafeBrowsing` | Яндекс SafeBrowsing: 1 / 0 |
| `hacked` | `SE::Google::Compromised` | Google «сайт взломан»: 1 / 0 |
| `curlie` | `Rank::Curlie` | в каталоге Curlie (бывший DMOZ): 1 / 0 |
| `social` | `Rank::Social::Signal` | VK: репостов главной, Pinterest: сохранений главной |
| `radar` | `Cloudflare::Radar` | Cloudflare: категории сайта |
| `trails` | `SecurityTrails::Domain` | A, NS, MX, число поддоменов |

Наборы:

| `--checks` | Что входит |
|---|---|
| `default` (по умолчанию) | whois, archive, rkn, sqi, dns |
| `pbn` | whois, archive, rkn, safe_google, safe_yandex, hacked, ahrefs, moz, majestic, mustat, sqi |
| `all` | всё, кроме медленного `rkn_ap` |
| `safe` | safe_google + safe_yandex |

Наборы и отдельные проверки можно смешивать: `--checks pbn,trails,hosting`.

Если проверка по домену не удалась, появляется колонка `<проверка>: ошибка` со значением
«не получено». Нули в `safe_*`, `hacked`, `curlie` — нормальный ответ «нет», а не ошибка.

`rkn` находит только точное совпадение домена с реестром. Блокировки по маске (`*.site.ru`)
и по IP он не видит — для спорных доменов есть `rkn_ap` (медленнее, с капчей).

```powershell
python run.py ai -f questions.txt --engine all --site site.ru,competitor.ru --brand "Окна Века,okna veka"
python run.py ai -q "лучшие производители окон в Москве" --engine openai --model gpt-5 --site site.ru
```

| `--engine` | Парсер | Что даёт |
|---|---|---|
| `googleai` (по умолчанию) | `FreeAI::GoogleAI` | ответ Google AI Mode и **источники**; язык ru, google.ru; до 7 мин на вопрос |
| `openai` | `OpenAI::ChatGPT` — официальный API OpenAI | ответ модели по её знаниям, без поиска в интернете и без источников; модель `--model` (по умолчанию gpt-5-mini, проверены также gpt-5 и gpt-4.1-mini), `--max-tokens` (2000); ~7 с на вопрос; колонки «модель» и «токенов» |
| `duckai` | `FreeAI::DuckAI` | ответ Duck.ai (модель по умолчанию — `gpt-5.6-luna`, другая — `--model`) |

`--site` — домены через запятую: для каждого появятся колонки «в источниках» (есть ли домен в
источниках ответа) и «в тексте ответа» (упоминается ли домен или его имя до точки латиницей).
Русское написание бренда так не ловится: в тесте OpenAI написал «Википедия», и колонка
`wikipedia.org: в тексте ответа` осталась False. Для этого есть `--brand` — названия через
запятую в любом написании, по колонке «`«название»` в ответе» на каждое.

Ключ OpenAI — `OPENAI_API_KEY` в `.env` в папке скилла (тот же, что у других
скиллов), модель по умолчанию — `OPENAI_MODEL`. Запросы к OpenAI идут с сервера напрямую, без
прокси, и оплачиваются по тарифу OpenAI за токены. У моделей gpt-5 в `--max-tokens` входят и
рассуждения: на ответ в одно предложение ушло ~170 токенов. `--model` применяется ко всем
выбранным нейросетям, поэтому с `--engine all` его лучше не задавать.

| Лист | Колонки |
|---|---|
| `ответы` | нейросеть, вопрос, получено, ответ, источников, модель и токенов — всего, на вопрос, на ответ (openai), `<домен>: в источниках`, `<домен>: в тексте ответа`, `«бренд» в ответе` |
| `источники` | нейросеть, вопрос, №, url, домен, заголовок, фрагмент |

отвечают — см. «Заготовки: разбирайтесь сами». Устаревший API дополнений OpenAI — через `raw --parser
OpenAI::Completions --set model=gpt-3.5-turbo-instruct`, ключ подставится сам.

### `check` — проверить все методы

```powershell
python run.py check                          # все методы и заготовки, по 4 одновременно
python run.py check --only serp,suggest      # только эти команды
python run.py check --only domains:ahrefs    # ровно один метод: команда:метод
python run.py check --no-stubs --workers 3 --timeout 20
```

Прогоняет каждый метод на одном-двух маленьких запросах: выдачу — отдельно по каждому поисковику,
`domains` — по каждой проверке, плюс все заготовки (около 120 проверок; вся — около часа, дольше всех
Яндекс и Google AI Mode). Каждая проверка — отдельная команда скилла с пределом времени (`--timeout`,
минут). Итог — реестр `data\methods\aparser.json` в папке скилла: статус метода (работает / частично /
не работает / таймаут / нужен доступ), время, заметка, пример команды. Панель задач показывает его
**полосой кнопок наверху**, кнопки перекрашиваются по ходу проверки. Результаты самих проверок — в
`data\_check\<дата_время>\`, в список запусков панели они не попадают — там видна одна задача `check`
с этапами по группам. Повторная проверка части методов (`--only`) сохраняет статусы остальных.

У каждого метода постоянный id «команда:метод»: `serp:google`, `domains:rkn`, `ahrefs:ahrefs`,
`stub:keysso`. `--only` с двоеточием берёт ровно этот метод, без двоеточия — все, чьё имя начинается
так (`--only rkn` заденет и медленный `rkn_ap`, `--only ahrefs` — три разных метода Ahrefs). Из панели
то же самое делается кнопками (раздел «Панель задач» выше). Проверка из панели и из терминала
одновременно друг другу не мешают: реестр пишется под замком (`data\methods\aparser.lock`), каждая
меняет только свои строки.

**Только по требованию.** Сама проверка не запускается никогда: её нет в расписании и в других
командах, панель запускает её только по нажатию кнопки. Запускайте, когда нужно: после установки и
обновления A-Parser, при смене прокси или когда что-то перестало работать и надо понять, что именно.
Полная проверка тратит трафик прокси и капчу — около часа работы; один метод — от секунд до нескольких
минут.

**Если «не работает» почти всё подряд** — сначала `python run.py status` и лог A-Parser
(`python server.py log -n 50`). Строка `SOCKS5 error: Auth failed` значит, что у прокси кончился трафик
или подписка, а не что сломались парсеры: A-Parser при этом продолжает показывать тысячи «живых» прокси,
если проверка прокси в нём выключена. Пополните прокси и перепроверьте только упавшие методы через `--only`.

## Панель задач

Подробное руководство — [PANEL.md](PANEL.md): каждый элемент экрана, очередь проверок, сценарии, где лежат файлы,
как показать в панели свой скрипт, API панели, проблемы и решения. Здесь — коротко.

Каждый запуск команды пишет своё состояние в `data\_runs\`. Запустите панель в отдельном окне
терминала — `python panel.py` в папке скилла — и откройте `http://127.0.0.1:8770/` (порт занят —
`python panel.py --port 8771`). Страница обновляется сама каждые 2 секунды. Без панели скилл работает
как обычно.

Сверху вниз на панели:

1. **Полоса A-Parser** — версия, потоков в работе, заданий в очереди, живых прокси, баланс капчи.
2. **Блок методов** — какие методы скилла сейчас работают: итог последней проверки каждого на маленьком
   запросе (команда `check`, ниже). По умолчанию свёрнут в строку с итогами и пояснением; развернуть —
   треугольник или «развернуть», это запоминается в браузере. Цвет кнопки: зелёная — работает, жёлтая —
   частично, красная — не работает, фиолетовая — нужен доступ, серая — не проверялся, мигающая синяя —
   проверяется, мигающая пунктирная — в очереди. Фильтры: все / работают / не работают / не проверены.
3. **Идущие задачи** — развёрнутые карточки: этапы (каждый парсер — строкой), сколько сделано из
   скольких, успешно, прошло и сколько осталось, хвост лога.
4. **Завершённые** — блок, как у методов, свёрнут по умолчанию; внутри каждая задача — строка: итог,
   сколько заняла, ссылки на результаты, ошибка. Треугольник разворачивает задачу целиком.

**Проверка методов кнопками.** Всё сразу панель не проверяет — только то, что вы выбрали:

| Что нажать | Что проверится |
|---|---|
| сам метод в блоке методов | этот метод — кнопка сразу начинает мигать; под группой открывается карточка с командой и «копировать» |
| «▶ проверить» под названием группы | методы группы, видимые при текущем фильтре |
| «▶ проверить показанные (N)» | всё, что видно при фильтре «не работают» или «не проверены» (при «все» кнопки нет — чтобы не запустить часовую проверку одним нажатием) |

Проверки идут по одной: нажатия во время проверки встают в очередь. В строке блока — «▶ проверка: идёт
N · в очереди M» и кнопка «остановить»: очищает очередь и гасит проверку, методы возвращают прежний итог.
Проверку, запущенную из терминала, панель видит (кнопки мигают так же), но не останавливает — Ctrl+C в
том окне. Задача проверки подписана тем, что проверяли: «rkn · check», «rkn, moz, dns +2 · check».

Панель слушает только `127.0.0.1` — из интернета её не видно — и принимает запуск проверки только со
своей страницы: другой сайт, открытый в том же браузере, запустить её не может. «Не отвечает» у задачи —
процесс больше 30 секунд не присылал вестей: его закрыли или он упал, результата нет.

Формат файла запуска — простой JSON (`status`, `stages` с `total/done/ok`, `outputs`, `log`,
`heartbeat`, необязательный `title`); его может писать и ваш собственный скрипт — возьмите за образец
`progress.py`.

**Куки и токены** — в `.env` в папке скилла, переменными из таблицы. В командной
строке их не пишите: она остаётся в истории терминала. Обязательных нет — заготовка скажет, какой
переменной не хватает.

**Персональные данные.** Заготовки соцсетей и отзывов вырезают из ответа авторов, подписчиков,
email и телефоны посторонних людей — и в xlsx, и в json. Список полей — `drop_arrays` и
`drop_fields` в `cmd_stubs.py`.

**Как разбирать заготовку:**

1. `python run.py stub <имя> -q "…" --debug` — лог A-Parser по первому запросу: капча, код ответа,
   бан прокси, «Content mismatch», изменённая вёрстка — обычно причина видна там.
2. Посмотрите опции: `python -c "import aparser as ap, json; print(json.dumps(ap.options('SE::Brave'), ensure_ascii=False, indent=1))"`
   и документацию парсера на [a-parser.com/docs/parsers](https://a-parser.com/docs/parsers).
3. Меняйте по одной опции через `--set`: движок (`engine=browser`), число страниц, регион,
   повторы. Запускайте по одному запросу и без других тяжёлых команд параллельно.
4. Поищите парсер на форуме A-Parser: разделы «Версии» и «Техподдержка» — часто там уже есть
   ответ разработчика и номер версии с исправлением.
5. Заработало — сделайте из заготовки полноценную команду («Как добавить команду»): колонки с русскими
   названиями, нужные листы, и перенесите парсер в `catalog.py` в «работает».

**Не делали заготовок** для 6 парсеров, которые не запускаем: Wordstat (3) — риск блокировки
аккаунта, частотности берите из официального API Wordstat; массовая регистрация аккаунтов
Яндекса; рассылка пингов; сбор email. И для 7 служебных: сервисы капчи и SMS, Redis, локальный
сервер OpenAI. Балабоба не отвечает — Яндекс закрыл сервис.

Полный список всех 137 парсеров с итогами и командами — `python run.py parsers`.

**Keys.so и Вордкрафт.** `Rank::KeysSo` входит в Keys.so по куке `userlogin` из браузера после
входа в кабинет — токен API Keys.so ему не подходит. `SE::Yandex::WordCraft` входит в Яндекс как
обычный пользователь: логин и пароль по строке в `<папка A-Parser>\files\SE-Yandex\accounts.txt`;
ключ Search API Яндекса ему тоже не подходит. A-Parser входит в аккаунт с разных IP прокси —
Яндекс может попросить подтверждение по SMS или заблокировать вход, поэтому основной аккаунт
сюда не давайте.

## Ограничения и тонкости

- **Google: язык русский, город — нет.** С `gl=ru`, `hl=ru`, `lr=lang_ru` и google.ru выдача
  русскоязычная, но регион Google определяет по IP прокси. Прокси Premium Mix — мировые, и в
  тестах Google «видел» Бразилию и Косово: в выдаче встречались сайты из разных городов России.
  Опция `location` (город) выдачу ломала. Для выдачи конкретного города нужны российские прокси
  с геотаргетингом (Premium с городом) — не проверяли. Для позиций по России в Google это
  оценка, а не точные данные.
- **Яндекс — только через браузер, и медленно.** 27.09.2026 — 6–7 минут на запрос (26.09 было
  5–20 с). Режим без браузера (`engine=http`) по-прежнему не работает. Парсер
  `SE::Yandex::Position` не работает, поэтому позиции в Яндексе считаются по выдаче `SE::Yandex`.
- **Bing** — через `SE::Bing::Position`: обычный `SE::Bing` не отвечает. Регион выбрать нельзя:
  с `region=ru-RU` парсер ломается, без него выдача по русскому запросу русская. Нестабилен:
  в одиночном запуске ответил за 26 с, в прогоне рядом с другими командами — «не получено».
- **Reddit** иногда отдаёт заголовок поста обрезанным до первого слова — полный виден в адресе
  ссылки.
- **Google SafeBrowsing через A-Parser** ходит со встроенным общим ключом A-Parser, и квота этого
  ключа кончается — Google отвечает `429 Too Many Requests` на каждый запрос, повторы через другие
  прокси не помогают (лимит на ключе, а не на IP). Поэтому при `GOOGLE_SAFEBROWSING_KEY` в .env
  `safe_google` идёт напрямую в Google Safe Browsing API вашим ключом (бесплатно, 10 000 запросов в
  сутки, до 500 доменов в запросе). Ключ: console.cloud.google.com → создать проект → «APIs & Services»
  → включить «Safe Browsing API» → «Credentials» → «Create credentials» → «API key». Условия Google:
  Safe Browsing API — для некоммерческого использования, для коммерческого у Google есть Web Risk API.
  Без ключа — как раньше, через A-Parser.
- **Trends** — только мир и 5 лет, см. `trends`.
- **Поиск по картинке** — только Яндекс и только по прямой ссылке на файл, лучше JPG.
- **Telegram** — только публичные каналы; один пост на запрос, поэтому `--last 100` — это 100
  запросов.
- **MOZ** у русскоязычных сайтов: DA и Spam Score есть, списки ключей и конкурентов часто пустые.
- **Букварикс** — бесплатный ключ, до 1000 фраз на запрос; смысл «частотности 2» не
  документирован.
- **Нули — это ответ.** `safe_google`, `safe_yandex`, `hacked`, `curlie` = 0 значит «нет /
  чисто», KD = 0 — «лёгкая фраза».
- **Один запрос — не приговор.** Каталог (`parsers`) собран по одному запросу на парсер через
  мировые прокси. Если команда вдруг перестала работать — сначала `status`, потом 2–3 запроса
  через `raw`, потом форум A-Parser: там быстро появляются новости, когда Яндекс или Google
  что-то меняют.

## Одна лицензия и несколько компьютеров

- **Одна лицензия — один компьютер.** A-Parser запускается только на IP,
  прописанном в кабинете.
- **Перенести на другой компьютер** можно: смените IP в кабинете (A-Parser →
  Настройка IP), и на старом компьютере A-Parser перестанет запускаться.
  Переносится вся папка A-Parser вместе с `config\` при выключенной программе.
- **Работать на двух компьютерах одновременно** можно только с дополнительной
  лицензией: для Enterprise это $399 за каждый следующий компьютер (кабинет →
  Магазин → «Дополнительные IP»).
- **Несколько копий на одном компьютере** — бесплатно. Интерфейсом одной копии
  пользуется один человек: если зайдёт второй, первого выкинет. Для параллельной
  работы каждой копии задают свой порт в её `config\config.txt`, например
  `bind: 127.0.0.1:9092`, и свой `APARSER_API_URL` в `.env`.
- **Лицензия личная.** Перепродажа, сдача в аренду и любые формы совместного
  доступа запрещены, за это A-Parser блокирует лицензию без возврата денег.
  Одну лицензию на группу не покупайте.

**A-Parser на арендованном сервере.** Если IP дома меняется или у вас Mac, проще
арендовать сервер (VPS) на Windows с постоянным IP и поставить на него всё сразу:
A-Parser, Python, скилл и Claude Code. Работать с сервером — через «Подключение
к удалённому рабочему столу» Windows.

Скилл можно держать и на своём компьютере, а A-Parser — на сервере. Порт наружу
при этом не открывайте, подключайтесь через SSH-туннель:

```powershell
ssh -N -L 9091:127.0.0.1:9091 пользователь@IP_сервера
```

Пока команда работает, API сервера доступен у вас на `http://127.0.0.1:9091/API`,
и `.env` менять не нужно. На сервере должен работать SSH-сервер (в Windows Server —
компонент OpenSSH Server). `server.py start` и `stop` в такой схеме не работают,
A-Parser запускают на самом сервере, а `status` и все команды `run.py` работают.

Если всё же открываете порт в интернет, сначала поставьте надёжный пароль (шаг 3),
потом меняйте `bind` на `0.0.0.0:9091` и разрешайте порт в брандмауэре только для
своего IP.

## Папка data: что где лежит

Всё, что создаёт скилл, — в папке `data\` рядом с кодом. Она, как и `.env`, в `.gitignore`: в git
не попадает и при обновлении скилла не трогается.

```
C:\aparser\
├── .env                          ← ваши пароли и ключи
├── run.py, cmd_*.py, …           ← код скилла
└── data\
    ├── serp\                     ← по папке на каждую команду
    │   ├── 2026-09-29_1015_yandex.xlsx      ← таблица
    │   └── 2026-09-29_1015_yandex.json      ← ответ A-Parser целиком
    ├── domains\  moz\  ahrefs\  suggest\  …
    ├── screenshot\               ← таблица + подпапка с PNG на каждый запуск
    ├── extract-article\ …        ← у extract — по папке на режим
    ├── stub-<имя>\               ← заготовки
    ├── raw\                      ← команда raw
    ├── _runs\                    ← состояние запусков для панели
    ├── methods\                  ← реестр методов (кнопки панели) и его замок .lock
    ├── checks\                   ← вывод проверок, запущенных кнопкой в панели
    └── _check\                   ← результаты проверочных запросов команды check
```

- **Имя файла** — дата, время до минуты и метка: `--label`, если задали, иначе запрос, домен или
  источник. Два запуска одной команды с одной меткой в одну и ту же минуту дадут одно имя — второй
  перезапишет первый. Для серий задавайте `--label`.
- **`.xlsx` и `.json` с одним именем** — пара: таблица для работы и полный ответ, если в таблице
  чего-то не хватило (раздел «Общее для всех команд»).
- **Что можно удалять.** Любые результаты — по мере ненадобности. `_runs\`, `_check\` и `checks\` —
  служебные, их можно чистить целиком: панель просто перестанет показывать старые задачи. `methods\`
  лучше не трогать — пропадут итоги проверок, методы снова станут серыми.
- **Резервная копия** — скопировать `data\` и `.env`. Всё остальное можно скачать заново.

## Обновление скилла и A-Parser

### Скилл

Новая версия скилла выходит в репозитории курса. Ваши `.env` и `data\` при обновлении не
трогаются: их нет в репозитории.

**Если вы скачали курс через `git clone`** и работаете прямо в его папке:

```powershell
cd <папка курса>              # та, где лежат README.md курса и папка aparser
git pull
cd aparser
python -m pip install -r requirements.txt
python run.py check --only domains:dns
```

- `git log --oneline -- aparser` — что изменилось.
- Если вы сами правили файлы скилла, `git pull` может отказаться. Тогда: `git stash`, `git pull`,
  `git stash pop` — и разберите конфликты, если git о них скажет.

**Если вы скопировали папку** (например, в `C:\aparser`) или скачивали архивом:

1. Скачайте новую версию: страница репозитория на GitHub → **Code → Download ZIP**, распакуйте.
2. Дождитесь окончания идущих команд и закройте панель (`Ctrl + C` в её окне).
3. Скопируйте всё из новой папки `aparser` поверх `C:\aparser` с заменой файлов. `.env` и `data\` в
   архиве нет — ваши останутся на месте. Собственные правки в файлах скилла при этом затрутся,
   сохраните их заранее.
4. `python -m pip install -r requirements.txt` и `python run.py check --only domains:dns`.
5. Если копировали скилл в `C:\Users\ВашеИмя\.claude\skills\aparser` для Claude Code — обновите и там.

Последняя команда обновляет реестр методов: в панели появятся новые методы, если они есть, а
старые итоги сохранятся.

### A-Parser

Обновления A-Parser входят в лицензию на 6 месяцев после покупки, дальше продлеваются платно
(на 27.09.2026 — $49 за 3 месяца). Порядок, проверенный на обновлении 1.2.3390 → 1.2.3656:

1. Кабинет → **A-Parser → Загрузки** → **Обновить**. Сборка архива занимает около минуты; окно может
   показать «Ошибка обновления», хотя версия сменилась, — смотрите на «Текущая версия», при
   необходимости перезагрузите страницу. Скачайте архив для Windows x64.
2. `python server.py stop`.
3. Переименуйте `C:\A-parser` в `C:\A-parser-old` — это копия на случай отката.
4. Распакуйте новый архив в `C:\A-parser`.
5. Перенесите из старой папки в новую:
   - из `config\`: `config.db`, `queue.db`, `scheduler.db`, папки `tasks` и `unique`;
   - `config\config.txt` со строкой `bind: 127.0.0.1:9091` — **обязательно**, иначе A-Parser снова
     станет доступен извне (шаг 2);
   - `files\proxy\`, `results\`, `queries\`.
   Папки `files\Rank-CMS` и `files\tools` не переносите — новая версия создаёт свои.
6. `python server.py start`. Первый старт после обновления докачивает компоненты (у нас — около
   900 МБ) и может занять несколько минут.
7. `python server.py status` — должна быть новая версия. Затем в панели проверьте методы, которыми
   пользуетесь, или запустите полную проверку `python run.py check` (около часа).
8. Всё работает — старую папку `C:\A-parser-old` можно удалить (она занимает 3–4 ГБ). Не работает —
   `python server.py stop`, верните старую папку на место и запустите снова.

Смена версии меняет и парсеры: что-то чинится, что-то может сломаться. Поэтому после обновления
верьте панели, а не таблице «что работает» в этом README — она снята на 1.2.3656.

## Частые ошибки

| Что видите | Причина | Что делать |
|---|---|---|
| `A-Parser не отвечает на http://127.0.0.1:9091/API` | программа не запущена | `python server.py start` |
| `ответил не как API A-Parser` | неверный `APARSER_API_URL` | адрес должен кончаться на `/API`, порт — как в `bind` |
| `A-Parser не принял пароль` | пароль в `.env` не совпадает с паролем интерфейса | исправить `APARSER_API_PASSWORD`; забытый пароль сбрасывается запуском с `-resetpassword` |
| `start` ждёт 3 минуты и сдаётся | A-Parser падает при старте, часто на старом тяжёлом задании | `python server.py log`, затем `python server.py stop` и `python server.py start --stoptasks` |
| A-Parser не стартует, в логе `Some error` или segmentation error | IP компьютера не совпадает с IP в кабинете | кабинет → A-Parser → Настройка IP |
| `aparser.exe` закрывается через 5 секунд без лога | бывает на Windows Server | запускать `aparser-core.exe` — `server.py` так и делает |
| В логе `IO error … cannot write` или `Permission denied` | файлы блокирует служба индексации Windows | `Win + R` → `services.msc` → Windows Search → Тип запуска «Отключена» → Остановить |
| Нестабильная работа, падения | антивирус: известны проблемы с Norton Internet Security, Emsisoft Anti-Malware, Guard Mail.ru | добавить папку A-Parser в исключения, Guard Mail.ru удалить |
| В логе `Out of memory!` | слишком много потоков или тяжёлое задание | уменьшить `--threads` |
| Почти все запросы «получено = False», в логе `596 SOCKS proxy error: SOCKS5 error: Auth failed` | кончился трафик или подписка прокси (счётчик живых прокси может этого не показывать) | пополнить прокси в кабинете a-parser.com, затем перезапустить неполученное |
| `safe_google`: `429 Too Many Requests` | кончилась квота общего ключа Google SafeBrowsing у A-Parser | свой ключ `GOOGLE_SAFEBROWSING_KEY` в `.env` — см. «Ограничения и тонкости» |
| `неизвестные опции [...]` | опечатка в `--set` или опция переименована в новой версии | посмотреть `ap.options("<парсер>")` и взять точное имя |
| `Нет парсера X` | неверное имя или парсера нет в вашей версии | список: `ap.available_parsers()` |
| Много «НЕ получено» | кончился трафик прокси, капча, блокировка | `server.py status`, перезапустить только неполученные, уменьшить `--threads` |
| Выдача Google пустая или со ссылками `google.com/goto` | сломано в 1.2.3390 | обновить A-Parser |
| `http`: код 503 и title «Идёт проверка вашего браузера» | защита от ботов | повторить с `--browser` |
| `живых прокси: всего 0` | пакет кончился или неверная ссылка в `sites.txt` | проверить кабинет и ссылку, перезапустить A-Parser |
| `CapMonster: баланс не проверен` | нет `CAPMONSTER_KEY` в `.env` или нет сети | проверить `.env` |
| `Неизвестный поисковик` / `Неизвестные проверки` | опечатка в `--engine` / `--checks` | список — в тексте ошибки и в `-h` |
| Команда идёт очень долго | браузерные парсеры под нагрузкой | не запускать несколько тяжёлых команд одновременно |
| Google вернул выдачу не того региона | регион — по IP прокси | см. «Ограничения и тонкости» |
| `byimage`: «получено = False» | не прямая ссылка на картинку или PNG | дать прямой адрес JPG-файла |
| `telegram`: 0 постов | канал закрыт или его нет, страница `t.me/s/<канал>` пустая | проверить канал в браузере |
| Панель: «нет связи с панелью» | панель не запущена | `python panel.py` в отдельном окне |
| Панель: нет блока методов или кнопок проверки | ещё не было проверки или реестр старого формата | `python run.py check --only domains:dns`; остальное — [PANEL.md](PANEL.md), «Проблемы и решения» |
| Второй результат затёр первый | та же команда с той же меткой в ту же минуту | задавать `--label` |

Лог A-Parser по одному запросу:

```python
import aparser as ap
r = ap.one("SE::Yandex", "окна", {"engine": "browser", "lr": 213, **ap.captcha("SE::Yandex")}, log=True)
print("\n".join(r["_log"]))
```

## Вопросы и ответы

**Нужен ли Claude Code?** Нет. Все задачи ставятся командами `python run.py …`. Claude Code удобен,
если хочется просить словами («сними позиции…») и не помнить параметры — шаг 9.

**Подойдёт лицензия Lite или Pro?** Нет. Управление через API есть только в Enterprise, а скилл
работает именно через API.

**Работает ли на Mac и Linux?** На macOS A-Parser запускается только через Docker — проще арендовать
сервер на Windows. На Linux A-Parser работает, команды `run.py` тоже, но `server.py start` и `stop`
рассчитаны на Windows. Подробнее — «Что понадобится и сколько стоит». Мы проверяли скилл только на
Windows.

**Сколько это стоит в месяц?** Лицензия разовая, дальше платите за прокси (пакет или трафик), капчу
(у нас — центы в день на тестах) и, по желанию, продление обновлений A-Parser. Цифры — «Что
понадобится и сколько стоит» и «Скорость и расходы».

**Как понять, какие команды у меня работают?** Откройте панель задач: блок методов показывает итог
последней проверки каждого метода, нужный проверяется кликом. Таблицы в этом README сняты у нас
27.09.2026 на A-Parser 1.2.3656 — у вас может отличаться.

**Почему «получено = False», хотя данные на сайте есть?** Это не «нет данных», а «не удалось
получить»: капча, бан, кончились прокси. Скилл уже повторил такие запросы через 30 секунд.
Перезапустите их отдельно — список печатается в конце — и загляните в `python server.py status`.

**Почему в таблице меньше данных, чем на сайте сервиса?** Скилл берёт бесплатные версии сервисов, а
у них лимиты: MOZ отдаёт по 7 записей в списках, Ahrefs — 20 доноров, Букварикс — до 1000 фраз на
запрос. Больше из них не получить.

**Что за лист «прочие поля» в таблице?** Всё, что пришло от A-Parser, но команда не разложила по
основным листам. Ничего не теряется молча — «Общее для всех команд».

**Можно ли запускать несколько команд одновременно?** Можно, в разных окнах. Но браузерные парсеры
(Яндекс, Google, Рамблер, YouTube, Google AI Mode) под нагрузкой замедляются в разы, и капчи
становится больше. Тяжёлые команды лучше по одной.

**Можно ли снять позиции Google по конкретному городу?** Язык — да, город — нет: Google определяет
регион по IP прокси, а прокси мировые. Для Яндекса город задаётся `--lr` и работает.

**Где частотности Wordstat?** Не здесь: парсер Wordstat в A-Parser требует аккаунт Яндекса и рискует
им. Частотности берите через официальный API Wordstat.

**Можно ли отдавать таблицы клиентам?** Да: логины и пароли прокси из результатов вырезаются,
данных посторонних людей в них нет — «Безопасность…».

**Как перенести скилл на другой компьютер?** Скопируйте папку скилла вместе с `.env` и `data\`. Сам
A-Parser — по разделу «Одна лицензия и несколько компьютеров».

**Как удалить скилл?** Удалите его папку. A-Parser, прокси и капча от этого не меняются. Если
копировали скилл в `C:\Users\ВашеИмя\.claude\skills\aparser` — удалите и там.

**Метод из заготовок не работает — что делать?** Это ожидаемо: заготовки добавлены, но не проверены.
Порядок разбора — «Заготовки: разбирайтесь сами»; когда заработает — перенесите в команду по «Как
добавить команду».

**Как обновиться?** Раздел «Обновление скилла и A-Parser»: `.env` и результаты при обновлении не
теряются.

## Работа из Python

```python
import sys
sys.path.insert(0, r"C:\aparser")
import aparser as ap
from common import run

ap.ping()                                              # True, если A-Parser отвечает
r = ap.one("Net::Whois", "example.ru")                 # один запрос → словарь
rows = run("Rank::MOZ", ["site.ru", "shop.ru"])        # пачка, капча подставится сама
for r in rows:
    print(r["query"], r["success"], r.get("authority"), r.get("spam"))
```

| Функция | Что делает |
|---|---|
| `ap.call(action, data)` | любой метод API (`info`, `getTasksList`, `addTask` …); ошибка — `APError` |
| `ap.one(parser, query, overrides, log=False)` | один запрос; `log=True` — лог A-Parser по запросу в `_log` |
| `ap.bulk(parser, queries, overrides, threads=5, batch=50, keep=())` | пачка запросов порциями |
| `common.run(parser, queries, overrides, threads, keep)` | то же + пресеты капчи |
| `ap.captcha(parser)` | пресеты капчи, которые нужны парсеру |
| `ap.options(parser)` / `ap.schema(parser)` | опции и их значения / поля результата |
| `ap.available_parsers()` | список парсеров версии |
| `ap.live_proxies(checker)` / `ap.capmonster_balance()` | прокси / баланс капчи |

У каждого результата есть `query`, `success` (1 — получено) и `retries`. Поля `proxy`, `pages`,
`data`, `headers` удаляются (`keep=("data",)` — оставить HTML). Массивы (выдача, беклинки)
приходят списками словарей.

Импорт отдельных команд: `import cmd_search`, `cmd_search.serp_rows("google", ["окна"], args)` —
`args` должен содержать те же поля, что и параметры командной строки.

## Как добавить команду

1. Проверить парсер через `raw` на 2–3 запросах. Опции — `ap.options(...)`, поля —
   `ap.schema(...)`.
2. Написать функцию `cmd_<имя>(a)` в подходящем `cmd_*.py` по образцу соседей:
   `read_items(a)` → `run(парсер, запросы, опции, threads=a.threads)` → список словарей с
   русскими названиями колонок → `report_failed(rows)` → `save("<имя>", метка, {"лист": строки}, rows)`.
3. Зарегистрировать в `register(sub)` того же модуля: `sub.add_parser(...)`, `add_io(p)`, свои
   параметры, `p.set_defaults(func=cmd_<имя>)`.
4. Обновить `catalog.py` (какой командой вызывается парсер), этот README и `SKILL.md`. Можно попросить Claude Code — он пройдёт эти шаги сам.

Правила: результаты — только через `save()` в `data\<команда>\`; поле `proxy` не
возвращать; для Яндекса — `engine=browser`; персональные данные посторонних людей (авторы
комментариев, подписчики, email) не выгружать.

## Безопасность, персональные данные и куда уходят данные

- **Пароль API, ключ CapMonster и доступы прокси** лежат только в `.env` на вашем
  компьютере. `.gitignore` не пускает его и папку `data\` в git, если выложите
  скилл на GitHub.
- **Запросы** A-Parser отправляет через ваши прокси в Яндекс, Google, Ahrefs, на
  серверы Whois, в веб-архив и на проверяемые сайты. Реестр РКН скачивается с
  antifilter.download.
- **Капчи** — картинки и ключи страниц — уходят в CapMonster.
- **Результаты** остаются у вас в `data\`. Логин и пароль прокси из них
  вырезаются, поэтому таблицы можно отдавать клиентам и коллегам.
- С Claude Code то, что он читает — ваши просьбы, таблицы, вывод команд, —
  отправляется в Anthropic.
- A-Parser слушает только `127.0.0.1:9091`: из интернета его не видно (шаг 2).
- Не включайте в настройках A-Parser `allow_dangerous_node_modules` и удалённый
  редактор JS без необходимости.
- **Персональные данные.** Из соцсетей скилл берёт контент и счётчики. Имена авторов
  комментариев YouTube и Reddit, списки подписчиков TikTok, email из профилей не выгружаются —
  ни в xlsx, ни в json. Сбор email (`HTML::EmailExtractor`) не подключён.
- Телефоны и адреса в `maps` — данные организаций из публичных карточек, для анализа
  конкурентов в локальном поиске, а не для рассылок.
- Ответы OpenAI (`ai --engine openai`) — вопросы уходят в OpenAI по вашему ключу.

| ИКС | индекс качества сайта Яндекса |
| Дроп | домен, срок регистрации которого кончился: он освободился или вот-вот освободится |
| PBN | сеть своих сайтов (часто на дропах), с которых ставят ссылки на основной сайт |
| Подклейка | 301-редирект с домена на другой домен — видно в веб-архиве |
| Whois, RDAP | сведения о регистрации домена: регистратор, даты, NS. RDAP — новый формат того же |
| Статусы домена | `clientHold` — регистратор приостановил домен, сайт не открывается; `redemptionPeriod` — регистрация истекла, прежний владелец ещё может выкупить; `pendingDelete` — домен скоро освободится. У `.ru`, `.su`, `.рф` свои правила — дату освобождения показывает колонка «освобождается» |
| NS | DNS-серверы, которые обслуживают домен |
| A-запись, TTL | A-запись — IP-адрес сайта; TTL — сколько секунд этот ответ можно держать в кэше |
| Веб-архив | archive.org: снимки страниц сайта по датам |
| РКН | реестр запрещённых в России сайтов Роскомнадзора |
| SafeBrowsing | чёрные списки опасных сайтов (вирусы, фишинг) Google и Яндекса |
