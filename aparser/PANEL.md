# Панель задач скилла aparser

Панель задач — страница в браузере, на которой видно, что сейчас делает скилл: какие команды идут,
сколько запросов обработано, сколько осталось, где лежит результат. Там же видно, какие методы
A-Parser у вас сейчас работают, и их можно проверить нажатием кнопки.

Панель — часть скилла: файлы `panel.py`, `panel.html` и `progress.py` лежат в его папке.
Устанавливать ничего не нужно. Скилл работает и без панели, она только показывает.

```
 python run.py …  ──► пишет состояние запуска ──► data\_runs\<id>.json ─┐
 python run.py check ► пишет итоги методов ────► data\methods\aparser.json ─┤
                                                                            ├─► python panel.py ─► http://127.0.0.1:8770/
 A-Parser (API 127.0.0.1:9091) ◄── версия, потоки, прокси ─────────────────┘        (обновляется каждые 2 с)
 CapMonster ◄── баланс раз в минуту ───────────────────────────────────────┘
```

## 1. Зачем она нужна

**Долгие команды без обратной связи.** Выдача Яндекса через A-Parser идёт через встроенный
браузер: бывает, что один запрос занимает несколько минут, а список из 300 фраз — час. В терминале
в это время видна только строка раз в порцию. Панель показывает ход целиком: этапы, сколько сделано,
сколько успешно, сколько прошло и сколько примерно осталось.

**Что вообще работает.** Поисковики и сервисы меняются, прокси кончаются, после обновления
A-Parser какой-то парсер может сломаться. Если узнать об этом через полчаса большого прогона,
пропадут время, трафик прокси и деньги на капчу. Блок методов показывает итог последней проверки
каждого метода, а проверить нужный можно одним нажатием — за секунды или минуты, а не час.

**Где результат.** У каждой задачи — ссылки на готовые файлы: таблица скачивается прямо из панели.

## 2. Запуск и остановка

Откройте **отдельное окно** PowerShell (панель занимает окно, пока работает) и выполните в папке
скилла:

```powershell
cd C:\aparser
python panel.py
```

В окне появится строка:

```
Панель задач: http://127.0.0.1:8770/  (запуски — C:\aparser\data\_runs)
```

Откройте в браузере на этом же компьютере **http://127.0.0.1:8770/**. Страница обновляется сама
каждые 2 секунды — нажимать F5 не нужно.

| Что нужно | Как |
|---|---|
| Другой порт (8770 занят) | `python panel.py --port 8771` и открыть `http://127.0.0.1:8771/` |
| Остановить панель | `Ctrl + C` в её окне или закрыть окно. Идущие команды скилла не прервутся — они работают в своих окнах |
| Держать постоянно | можно: панель почти не нагружает компьютер и сама ничего не запускает, кроме проверок по вашим кнопкам |
| Запустить заново | та же команда; всё, что уже было, панель прочитает из файлов в `data\` |

Если порт занят, панель не «садится» на него молча, а пишет
`Порт 8770 занят — запустите с другим: python panel.py --port 8771` и выходит.

## 3. Что на экране

Сверху вниз четыре части.

### 3.1. Полоса A-Parser

```
● A-Parser 1.2.3656   потоков в работе: 0   заданий в очереди: 0   живых прокси: 9 892   капча: $3.89
```

| Что | Смысл |
|---|---|
| точка | зелёная — A-Parser отвечает по API; красная — «A-Parser не отвечает» и подсказка `python server.py start` |
| версия | версия A-Parser |
| потоков в работе | сколько запросов A-Parser выполняет прямо сейчас |
| заданий в очереди | сколько заданий ждёт своей очереди в A-Parser |
| живых прокси | сколько прокси A-Parser считает рабочими. **Осторожно:** если в проксичекере выключена проверка прокси, число не падает, даже когда трафик пакета кончился — смотрите лог A-Parser (`python server.py log`) и кабинет |
| капча | баланс CapMonster; `—` — в `.env` нет `CAPMONSTER_KEY` |

Данные A-Parser обновляются раз в 10 секунд, баланс капчи — раз в минуту. Полосы нет совсем, если
у скилла нет файла `.env`.

### 3.2. Блок методов

Какие методы скилла сейчас работают — итог последней проверки каждого метода на маленьком запросе.
Метод — это команда скилла с конкретным поисковиком или проверкой: `serp` по Google, `domains` с
проверкой `whois`, заготовка `keysso` и так далее. Всего их 123.

**Свёрнутый вид** (по умолчанию) — одна строка с итогами и пояснение:

```
▸ aparser — методы A-Parser   работает 90 · не работает 8 · нужен доступ 8 · не проверялся 16 · обновлено 28.09 19:46
  Какие парсеры A-Parser у скилла сейчас реально работают — … развернуть
```

Развернуть — треугольник `▸`, клик по названию или ссылка «развернуть». Браузер запоминает, что
блок развёрнут, и в следующий раз откроет его так же.

**Развёрнутый вид:** легенда цветов, фильтры и кнопки методов по группам (Выдача, Подсказки,
Ключевые слова, Проверка доменов, Ссылки и домены, Страницы, Тексты, Нейросети, Картинки и видео,
Прочее, Заготовки).

| Кнопка метода | Значит |
|---|---|
| зелёная | работает |
| жёлтая | частично: данные есть, но не все (у заготовок — «с данными 1 из 2») |
| красная | не работает или не уложился в предел времени; наведите мышь — будет причина |
| фиолетовая | нужен доступ: кука, токен или ключ в `.env` (у заготовок соцсетей, Keys.so, Google Ads) |
| серая с рамкой | не проверялся или не проверяется автоматически |
| синяя мигающая | проверяется прямо сейчас |
| синяя пунктирная мигающая | в очереди на проверку |

**Фильтры:** «все», «работают», «не работают» (красные и жёлтые), «не проверены / нужен доступ»
(серые и фиолетовые).

**Наведение** на метод — статус, сколько заняла проверка и заметка. **Клик** — метод ставится на
проверку (раздел 4) и под его группой открывается карточка:

```
Проверка доменов · whois — domains --checks whois                                          ✕
Статус: работает · проверено 28.09 19:44 · заняло 3 с
python run.py domains --checks whois -q example.com     [копировать]  [▶ проверить ещё раз]
```

В карточке — пример команды, которой метод проверялся: её удобно скопировать и запустить со своими
запросами.

Строка итогов у блока показывает и ход проверки:
`▶ проверка: идёт 2 · в очереди 5  [остановить]`.

### 3.3. Идущие задачи

Раздел «Сейчас идут» — развёрнутые карточки команд, которые работают прямо сейчас:

```
aparser · serp  [идёт]  29.09 10:15
serp --engine yandex,google -f queries.txt --pages 3
████████████░░░░░░░░░░░░░░░░░░  40 из 100 запросов · успешно 38 · 40%        прошло 12 мин 5 с · осталось ≈ 18 мин
SE::Yandex   ███████████████░░░   40 / 50   успешно 38   …
SE::Google   ░░░░░░░░░░░░░░░░░░    0 / 50   успешно 0
лог ▾
```

| Что | Смысл |
|---|---|
| заголовок | что запущено: скилл · команда (у проверок — что проверяют: «rkn · check»), время старта |
| строка под заголовком | параметры команды, как вы их набрали |
| общая полоса | сделано из скольких по всем этапам, сколько успешно, процент |
| прошло / осталось ≈ | «осталось» — оценка по средней скорости с начала; первые минуты она скачет |
| этапы | каждый парсер — строкой: полоса, сделано / всего, успешно, `✓` — этап закончен |
| лог | последние 14 строк вывода команды; у идущих раскрыт |

Порции запросов режутся так, чтобы прогресс обновлялся не реже пяти раз за этап.

**«Не отвечает»** (жёлтым) — задача числится идущей, но больше 30 секунд не присылала «пульс»:
окно закрыли, компьютер перезагрузился или процесс упал. Результата у неё нет, её нужно запустить
заново.

### 3.4. Завершённые

Блок «Завершённые — N», как и блок методов, по умолчанию свёрнут: итоги
(`готово 9 · готово: не всё получено 7 · ошибка 1 · последняя 29.09 06:49`) и пояснение. Закончившаяся
задача переезжает сюда сама.

Внутри каждая задача — одна строка:

```
▸ rkn · check  [готово]  29.09 06:50 · заняло 2 с · 1 из 1, успешно 1   check --only domains:rkn   aparser.json
```

| Статус | Значит |
|---|---|
| готово (зелёный) | всё получено |
| готово: не всё получено (жёлтый) | команда закончилась, но часть запросов без данных — капча, бан, кончились прокси. Их список — в конце лога, перезапустите их отдельно |
| ошибка (красный) | команда упала или её остановили; текст ошибки — под строкой |

Треугольник `▸` разворачивает задачу целиком — этапы и лог. Ссылка на результат: `.xlsx`
скачивается, `.png` и `.json` открываются в браузере.

Показываются последние 40 запусков.

## 4. Проверка методов кнопками

### 4.1. Как проверить

| Что нажать | Что проверится |
|---|---|
| сам метод | этот метод; кнопка сразу начинает мигать, под группой открывается карточка |
| «▶ проверить» под названием группы | методы этой группы, видимые при текущем фильтре |
| «▶ проверить показанные (N)» у фильтров | всё, что видно при фильтре «не работают» или «не проверены». При фильтре «все» этой кнопки нет специально: полная проверка — около часа и заметный расход прокси и капчи, одним нажатием её не запустить |
| «▶ проверить ещё раз» в карточке | этот метод повторно |

Метод, который уже в очереди или проверяется, повторно не ставится: клик по нему просто открывает
карточку.

### 4.2. Очередь

- На скилл идёт **одна проверка за раз**. Всё, что нажато во время неё, копится в очереди и уходит
  следующей пачкой, когда текущая закончится.
- Если проверка запущена **из терминала** (`python run.py check …`), кнопки мигают так же, в строке
  блока появляется «запущена не из панели», а очередь панели ждёт её окончания.
- Проверка из панели и из терминала одновременно друг другу не мешают: каждая меняет в реестре
  только свои строки.

### 4.3. Остановка

Кнопка **«остановить»** в строке блока:

1. очищает очередь;
2. гасит идущую проверку вместе с дочерними командами;
3. помечает её задачу «ошибка: остановлено кнопкой в панели»;
4. методы, которые не успели проверить, возвращают прежний итог с заметкой «проверку прервали —
   показан прежний итог».

Задания, которые уже ушли в A-Parser, он доделает сам — это секунды или минуты. Проверку,
запущенную из терминала, панель не останавливает: `Ctrl + C` в том окне.

### 4.4. Что происходит внутри

Нажатие — это запуск обычной команды скилла:

```powershell
python run.py check --only domains:whois,serp:google
```

- `domains:whois` — **id метода** «команда:метод». Точные id видны в строке примера в карточке
  метода: `python run.py domains --checks whois …` → `domains:whois`.
- Каждый метод проверяется отдельной командой скилла на одном-двух маленьких запросах, по 4 метода
  одновременно, с пределом 30 минут на метод.
- Итог каждого метода записывается в реестр `data\methods\aparser.json` — кнопка перекрашивается.
- Результаты самих проверочных запросов — в `data\_check\<дата_время>\`, вывод проверки, запущенной
  кнопкой, — в `data\checks\aparser_<дата-время>.log`.

**Сколько стоит.** Один метод — от 1–2 секунд (DNS, Whois, РКН) до нескольких минут (Яндекс через
браузер, Google AI Mode). Методы через прокси тратят немного трафика, Яндекс, Google, Ahrefs,
Majestic и Bing — ещё и капчу (центы). Полная проверка всех 123 методов — около часа.

### 4.5. Как статус выставляется

| Статус | Когда |
|---|---|
| работает | команда отработала и получила данные по всем запросам (повтор с последующим успехом — тоже «работает») |
| частично | у заготовки данные есть не по всем запросам |
| не работает | команда упала, не создала файл результата или запросы остались без данных и после повтора |
| таймаут | не уложилась в предел времени |
| нужен доступ | заготовке нужна переменная в `.env` (кука, токен) |
| не проверяется | метод нельзя проверить автоматически (например, нужна ссылка на реальную карточку Wildberries) |

## 5. Типовые сценарии

**Сразу после установки.** Блока методов ещё нет — он появляется после первой проверки:

```powershell
python run.py check --only domains:dns
```

Дальше фильтр «не проверены» → «▶ проверить» у групп, которые вам нужны: «Выдача», «Проверка
доменов», «Ссылки и домены». Всё сразу проверять не обязательно.

**Пополнили или сменили прокси.** Фильтр «не работают» → «▶ проверить показанные». Если красное
позеленело — дело было в прокси.

**Перед большим прогоном.** Кликните метод, который собираетесь гонять (например, `ahrefs` в группе
«Ссылки и домены»), и дождитесь зелёного. Потом запускайте прогон и следите за ним в «Сейчас идут».

**Что-то перестало работать.** Клик по методу → в карточке заметка (последняя строка вывода) →
`python server.py status` и `python server.py log -n 50`. Строка `SOCKS5 error: Auth failed` в логе
A-Parser — кончился трафик прокси, а не сломался парсер.

**После обновления A-Parser.** Фильтр «все» → «▶ проверить» по группам, которыми пользуетесь, или
полная проверка из терминала `python run.py check` (около часа).

**Следить за долгой командой.** Запустите её в терминале как обычно — через секунду она появится в
«Сейчас идут» с оценкой, сколько осталось.

## 6. Где лежат файлы

Всё — в папке `data\` скилла. Она в `.gitignore`, в git не попадает.

| Что | Где |
|---|---|
| Состояние каждого запуска (для панели) | `data\_runs\<дата-время-номер процесса>.json` |
| Реестр методов (кнопки) | `data\methods\aparser.json`, рядом `aparser.lock` — замок, чтобы две проверки не писали одновременно |
| Вывод проверок, запущенных кнопкой | `data\checks\aparser_<дата-время>.log` |
| Результаты проверочных запросов | `data\_check\<дата_время>\…` |
| Результаты ваших команд | `data\<команда>\<дата_время>_<метка>.xlsx` и `.json` |

Панель ничего не удаляет. Старые файлы из `data\_runs\` и `data\_check\` можно удалять руками —
панель просто перестанет их показывать. Реестр `data\methods\aparser.json` лучше не удалять: пропадут
итоги проверок (блок методов появится снова после следующей проверки, но все методы будут серыми).

## 7. Настройки

Обычно ничего менять не нужно. Для особых случаев — переменные окружения (задаются в том же окне
PowerShell перед запуском, например `$env:TASK_PANEL_RUNS = "D:\runs"`):

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `TASK_PANEL_RUNS` | `data\_runs` в папке скилла | где панель ищет файлы запусков и куда их пишет `progress.py` |
| `TASK_PANEL_METHODS` | `data\methods` рядом с папкой запусков | где лежат реестры методов |
| `APARSER_CONFIG` | `.env` в папке скилла | откуда брать адрес и пароль API A-Parser и ключ CapMonster для полосы A-Parser |

Если меняете `TASK_PANEL_RUNS`, задайте его одинаково и для панели, и для команд скилла — иначе
панель не увидит их запуски.

## 8. Безопасность

- Панель слушает только `127.0.0.1` — с других компьютеров и из интернета её не видно.
- **Запуск проверки** принимается только со страницы самой панели: запрос должен прийти на
  `127.0.0.1` или `localhost` с тем же портом, со служебным заголовком `X-Panel: 1` и без чужого
  адреса страницы (`Origin`). Другой сайт, открытый в том же браузере, запустить проверку не может.
- Запускается только команда проверки из реестра скилла и только с id методов, которые в реестре
  есть. Произвольную команду через панель выполнить нельзя.
- Файлы по ссылкам панель отдаёт только из папки `data\` скилла.
- Ключи из `.env` панель в браузер не передаёт — только баланс капчи и числа A-Parser.
- Панель ничего не удаляет. Единственное, что она меняет в чужих файлах, — пометка «остановлено
  кнопкой в панели» у задачи, которую вы остановили.

**Панель на удалённом сервере.** Если A-Parser и скилл стоят на сервере, откройте панель через
SSH-туннель, оставив **тот же номер порта**:

```powershell
ssh -N -L 8770:127.0.0.1:8770 пользователь@IP_сервера
```

и откройте у себя `http://127.0.0.1:8770/`. С другим локальным портом страница откроется, но кнопки
проверки работать не будут — панель сверяет порт в адресе с тем, на котором работает сама.

## 9. Как показать в панели свой скрипт

Любой ваш скрипт на Python может появиться в панели карточкой, как команды скилла. Проще всего —
через `progress.py` из папки скилла:

```python
import sys
sys.path.insert(0, r"C:\aparser")        # папка скилла
import progress

run = progress.start("my-script", "export", sys.argv[1:])   # скилл, команда, параметры — для заголовка
run.title("выгрузка отчёта · export")                        # необязательно: свой заголовок карточки
st = run.stage("клиенты", 120)                               # этап: имя и сколько всего шагов
for n in range(1, 121):
    ...                                                      # ваша работа
    run.advance(st, n, n)                                    # сделано n, из них успешно n
run.output(r"C:\aparser\data\my\report.xlsx")                # ссылка на результат (только из data\ скилла)
run.finish("done")                                           # или run.finish("error", "текст ошибки")
```

- `progress.start` сам шлёт «пульс» раз в 5 секунд отдельным потоком и дублирует всё, что скрипт
  печатает, в лог карточки.
- Если скрипт завершится без `finish`, запуск закроется со статусом «готово» при выходе.
- Этапов может быть сколько угодно; общий процент и «осталось» панель считает по всем.

Можно и без `progress.py` — достаточно писать JSON-файл в `data\_runs\`:

```json
{
  "id": "20260929-101500-12345",
  "skill": "my-script",
  "command": "export",
  "args": "export --client all",
  "title": "выгрузка отчёта · export",
  "pid": 12345,
  "status": "running",
  "started": "2026-09-29T10:15:00",
  "updated": "2026-09-29T10:16:02",
  "heartbeat": "2026-09-29T10:16:05",
  "finished": null,
  "stages": [
    {"name": "клиенты", "total": 120, "done": 40, "ok": 38, "started": "2026-09-29T10:15:01", "finished": null}
  ],
  "outputs": ["C:\\aparser\\data\\my\\report.xlsx"],
  "log": ["обработано 40 из 120"],
  "error": null
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | имя файла без `.json`; удобно «дата-время-номер процесса» |
| `skill`, `command`, `args` | да | что запущено — видно в заголовке и строке под ним |
| `title` | нет | заголовок карточки вместо «скилл · команда» |
| `status` | да | `running`, `done` или `error` |
| `started`, `finished` | да | время `ГГГГ-ММ-ДДTЧЧ:ММ:СС`; `finished` — `null`, пока идёт |
| `heartbeat` | да | обновлять раз в 5–10 секунд, пока идёт, — иначе через 30 секунд задача станет «не отвечает» |
| `stages` | нет | этапы: `name`, `total`, `done`, `ok`, `finished` — по ним считаются прогресс и «осталось» |
| `outputs` | нет | полные пути к результатам; ссылками открываются только файлы из `data\` скилла |
| `log` | нет | последние строки вывода (панель показывает 14) |
| `error` | нет | текст ошибки при `status: "error"` |

Файл пишите атомарно: сначала во временный `<id>.tmp`, потом переименуйте в `<id>.json` — тогда
панель не прочитает его наполовину записанным.

## 10. Реестр методов — формат

Нужен, если вы захотите сделать блок методов для своего набора скриптов. Реестр скилла пишет
команда `check` (`cmd_check.py`) — это готовый образец.

```json
{
  "skill": "aparser",
  "title": "aparser — методы A-Parser",
  "about": "Какие парсеры A-Parser у скилла сейчас реально работают — …",
  "updated": "2026-09-29T06:49:28",
  "check": {"python": "C:\\Program Files\\Python310\\python.exe", "cwd": "C:\\aparser",
            "args": ["run.py", "check", "--only", "{ids}"]},
  "methods": [
    {"id": "domains:whois", "group": "Проверка доменов", "name": "whois", "what": "domains --checks whois",
     "example": "python run.py domains --checks whois -q example.com",
     "status": "ok", "checked": "2026-09-29T06:50:01", "seconds": 3, "note": ""}
  ]
}
```

| Поле | Смысл |
|---|---|
| `skill` | имя скилла — по нему панель связывает реестр с задачами проверки |
| `title`, `about` | заголовок блока и пояснение под ним |
| `check` | чем проверять по кнопке: интерпретатор `python`, папка `cwd`, аргументы `args`, где `{ids}` заменяется на id через запятую. Первый аргумент должен быть файлом в `cwd`. Нет поля — у блока нет кнопок проверки |
| `id` | постоянный уникальный id метода; без него кнопки проверки у метода нет |
| `group`, `name`, `what` | группа, подпись кнопки, пояснение в карточке |
| `example` | команда для «копировать»; пусто — метод не проверяется автоматически |
| `status` | `ok`, `part`, `fail`, `timeout`, `need`, `skip`, `unknown`, `running` |
| `checked`, `seconds`, `note` | когда проверен, сколько занял, заметка (причина провала) |
| `run`, `prev_status`, `prev_note` | у метода в статусе `running`: какая проверка его ведёт и прежний итог. Если та проверка уже не идёт, панель показывает прежний итог |

Реестр пишется под замком (`<реестр>.lock` рядом): прочитать файл, поменять строку своего метода,
записать атомарно. Так проверки из панели и из терминала не затирают друг друга.

## 11. API панели

Для своих скриптов и отладки. Всё — на том же адресе, что и страница.

| Запрос | Что делает |
|---|---|
| `GET /` | страница панели |
| `GET /api/state` | всё состояние одним JSON: `now`, `runs` (запуски), `methods` (реестры), `checks` (очередь проверок), `aparser` (полоса A-Parser) |
| `GET /open?path=<полный путь>` | отдать файл результата (только из `data\` скилла) |
| `POST /api/check` | тело `{"skill": "aparser", "ids": ["domains:whois"]}` — поставить методы в очередь; ответ `{"queued": 1}` |
| `POST /api/check/stop` | тело `{"skill": "aparser"}` — очистить очередь и остановить проверку; ответ `{"stopped": true, "dropped": 0}` |

POST-запросы нужно слать с заголовками `Content-Type: application/json` и `X-Panel: 1` на
`127.0.0.1` или `localhost`. Пример из PowerShell:

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8770/api/check `
  -Headers @{"X-Panel" = "1"} -ContentType "application/json" `
  -Body '{"skill": "aparser", "ids": ["domains:whois", "domains:dns"]}'
```

| Ответ | Значит |
|---|---|
| 200 `{"queued": N}` | поставлено N методов (0 — они уже в очереди или проверяются) |
| 400 «таких методов в реестре нет» | неверный id или метод без проверки |
| 400 «в реестре нет команды проверки» | реестр старого формата — запустите любую проверку из терминала |
| 403 «только со страницы панели» | нет заголовка `X-Panel`, чужой адрес или порт |
| 404 «нет реестра методов» | неверное имя скилла или проверок ещё не было |

## 12. Проблемы и решения

| Что видите | Причина | Что делать |
|---|---|---|
| «нет связи с панелью — запущен ли python panel.py?» | панель не запущена или её окно закрыли | `python panel.py` в отдельном окне |
| `Порт 8770 занят` | на порту другая программа (или вторая панель) | `python panel.py --port 8771` |
| Нет блока методов | ещё не было ни одной проверки | `python run.py check --only domains:dns` |
| У методов нет кнопок проверки, клик только открывает карточку | реестр старого формата (до обновления скилла) | любая проверка из терминала пересоздаст его: `python run.py check --only domains:dns` |
| Метод мигает «в очереди» и не начинается | идёт другая проверка (из панели или из терминала) | дождаться её; в строке блока видно, сколько идёт и сколько ждёт |
| «таких методов в реестре нет» | реестр устарел после обновления скилла | проверка из терминала обновит список методов |
| «только со страницы панели» | панель открыта не по `127.0.0.1`/`localhost` или через туннель с другим портом | открыть `http://127.0.0.1:<порт панели>/` |
| Задача «не отвечает» | окно команды закрыли, компьютер перезагрузился или процесс упал | запустить команду заново |
| Проверка по кнопке сразу «ошибка» | команда проверки упала | лог — `data\checks\aparser_<дата-время>.log` |
| Метод с заметкой «проверку прервали — показан прежний итог» | проверку остановили или её окно закрыли | кликнуть метод ещё раз |
| Почти всё красное после проверки | кончился трафик прокси или A-Parser не отвечает | `python server.py status` и `python server.py log -n 50` — ищите `Auth failed` |
| Красная точка «A-Parser не отвечает» | A-Parser не запущен | `python server.py start` |
| Нет полосы A-Parser | нет `.env` в папке скилла | шаг 7 README |
| «капча: —» | нет `CAPMONSTER_KEY` в `.env` или нет связи с CapMonster | вписать ключ; на работу не влияет |
| Ссылка на результат: «Можно открывать только файлы из папки data скилла» | файл лежит вне `data\` | открыть его в проводнике |
| Задача не появляется в панели | команду запустили с другим `TASK_PANEL_RUNS` или из другой копии скилла | запускать команды и панель из одной папки |

## 13. Ограничения

- Показываются последние 40 запусков; более старые остаются в `data\_runs\`, но на странице их нет.
- Проверку, запущенную из терминала, панель видит, но не останавливает.
- Остановка гасит проверку, но задания, уже отправленные в A-Parser, он доделает сам.
- Свёрнут или развёрнут блок — запоминается в конкретном браузере; в другом браузере блоки снова
  свёрнуты.
- Панель работает только на том компьютере, где запущена (или через SSH-туннель с тем же портом).
- Панель не хранит историю проверок: у метода виден только итог последней.
