# yadisk-rescue — спасти файлы с Яндекс Диска

Скилл забирает с Диска то, что Яндекс ещё отдаёт. Все запросы идут изнутри
вкладки Диска в браузере пользователя, теми же методами, что и сам сайт.
Файлы — строго по одному, с паузами. Подробная инструкция для человека —
`README.md`. Отправляй туда пользователя, если он хочет всё сделать сам.

Команды запускать из папки скилла. На macOS — `python3`. На Windows лучше
PowerShell: Git Bash портит пути вида `/disk/...` (скрипт это чинит, но
лишний раз не рискуй).

## Правила, которые нельзя нарушать

1. **Один прогон за раз.** Не запускать второй `fast`/`slow`/`all`/`index`,
   пока идёт первый: скрипт откажет сам, обходить блокировку нельзя.
   Параллельные потоки и одновременное скачивание — нет.
2. **Паузы не уменьшать** (`--pause-min/--pause-max`, таймауты), даже если
   пользователь торопит. Объяснить: частые запросы → капча → блок на время.
3. **Не открывать новых вкладок и окон с Диском и не кликать во вкладке.**
   Работа только через `rescue.py`, который читает уже открытую вкладку.
4. **«СТОП» в журнале — остановиться.** Не перезапускать сразу. Сказать
   пользователю: открыть окно браузера, пройти капчу или войти заново,
   подождать 15–30 минут, и только потом запускать ту же команду.
5. **Ничего не удалять** ни на Диске (скрипт этого и не умеет), ни локально:
   файлы `.part` нужны для докачки, превью — страховка.
6. **Пароль не спрашивать.** Вход в Яндекс пользователь делает сам, в окне
   браузера.

## Порядок работы

### 1. Подготовка

```
python --version                      # нужен 3.9+
pip install -r requirements.txt       # websocket-client + requests
```

Спросить, куда сохранять, или предложить диск, где больше места. Свободное
место проверить, например `Get-PSDrive -PSProvider FileSystem`. Записать:

```
python rescue.py setup --out "D:\YandexDisk_rescue"
```

### 2. Браузер и вход

```
python start_chrome.py
```

Откроется отдельное окно (отдельный профиль `~/.yadisk-rescue/chrome-profile`,
обычный браузер пользователя не трогается). Попросить пользователя войти в
Яндекс и открыть Диск. Окно не закрывать до конца работы. Дождаться ответа
«вошёл», затем:

```
python rescue.py ping
```

Нужна строка «Запрос к Диску прошёл». Показать пользователю аккаунт и
занятое место, чтобы он убедился, что вошёл туда, куда нужно.

Если `ping` пишет «Chrome на порту … недоступен» — окно закрыто, снова
`start_chrome.py`. «Нет вкладки Яндекс Диска» — в окне должен быть открыт
адрес `disk.yandex.ru/client/...`.

### 3. Список и выбор

Спросить, где фотоархив. Если не знает, посмотреть корень:
`index --root "/disk"` (на большом Диске это долго, лучше сначала узнать
папку).

```
python rescue.py index --root "Фото"        # можно без /disk
python rescue.py report --root "Фото"
```

Раздел «Фото» на сайте — это ещё и безлимитная автозагрузка с телефона. Она
лежит отдельно от «Файлов», в `/photounlim`: спросить про неё и собрать
отдельно (`index --root "/photounlim"`). Имена там — даты, порядок по имени =
по дате съёмки.

Показать таблицу из `report` как есть, с «Как читать» под ней. Спросить:
какие папки качать (номера или названия) и нужны ли видео. Сказать, сколько
это гигабайт и примерно сколько времени: около 12 с на файл в первом
проходе, плюс около 2 с на превью.

По желанию — оценка одной папки без скачивания:

```
python rescue.py check --root "Фото" --dirs "2013" --sample 40
```

Пересказать итог словами: сколько превью живо, на каких серверах лежат
файлы. На октябрь 2026 серверы `nrg` отдавали файлы за секунды, а `klg` в
большинстве молчали или обрывались. Подавать это как наблюдение, не как факт
навсегда.

### 4. Запуск

Всегда в фоне, чтобы прогон не зависел от сессии:

```
python rescue.py start all --root "Фото" [--dirs "2013" "Отпуск 2015"] [--no-video]
```

`all` = фото по папкам порциями по 100 в порядке имён (превью 1280 сотни →
её оригиналы) → видео → повтор недокачанного (`slow`). `--no-retry` — без
повтора в конце: если повтор почти ничего не даёт, лучше запускать `slow`
отдельно через несколько дней. `--split-size 1` — раскладывать в подпапки
«большие (от 1 МБ)» / «маленькие (до 1 МБ)», включать до начала скачивания.

Пробный запуск на несколько файлов — `start fast ... --limit 5`.

### 5. Наблюдение

```
python rescue.py status      # идёт ли, последние строки журнала, итоги
python rescue.py stats --root "Фото" [--dirs ...]
```

Журнал — `<out>/_rescue/rescue.log`. Следить удобнее фильтром по
`закончен|СТОП|недоступен|нет открытой|ошибок API|Traceback` (например,
`tail -F ... | grep --line-buffered -E '...'`), без потока строк по каждому
файлу. Пользователю писать при смене этапа, при «СТОП» и в конце прохода. В
сообщениях давать полные пути к папкам с результатом.

Статусы файлов: `done` — оригинал целиком; `partial` — кусок в `.part`,
докачается; `timeout` — сервер молчал; `error` — ошибка Диска по файлу.

### 6. Итог и повторы

После прохода показать таблицу из `stats`: сколько оригиналов, сколько
частично, сколько не ответило, сколько превью. Под таблицей — «Как читать».
Предложить повтор через день-два:

```
python rescue.py start slow --root "Фото"
```

`slow` ждёт сервер до 60 с, продолжает оборванное, на файл даёт 3 попытки за
запуск. Новые файлы на Диске добавляются повторным `index` для той же папки,
статусы скачанного сохраняются.

## Куда что сохраняется

- оригиналы: `<out>/<путь на Диске без /disk>/...`, дата файла = дата съёмки;
- превью 1280: `<out>/_превью_1280/<путь>/...`;
- журнал и память: `<out>/_rescue/` (`rescue.log`, `state_*.json`, `run.lock`);
- настройки и профиль браузера: `~/.yadisk-rescue/` (переопределяется
  переменной окружения `YADISK_RESCUE_HOME`).

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `СТОП: ... captcha` / HTTP 401 / HTML вместо файла | правило 4: капча руками, пауза 15–30 мин, та же команда |
| `Уже идёт прогон (PID …)` | дождаться или `python rescue.py stop`, второй не запускать |
| Всё `timeout`, ни одного `done` подряд в нескольких папках | не ускорять; доделать превью, `slow` через день-два |
| `диск: ...` в журнале | кончилось место или слишком длинный путь — проверить место, выбрать `--out` покороче |
| Пользователь закрыл окно браузера | `start_chrome.py`; прогон ждёт вкладку до 30 мин сам |
