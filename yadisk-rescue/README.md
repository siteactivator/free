# Спасти файлы с Яндекс Диска через браузер: скилл yadisk-rescue

У Яндекс Диска авария в хранилище. Часть фото на сайте показывается серыми
квадратиками вместо превью, кнопка «Скачать» крутится и ничего не отдаёт,
программа «Яндекс Диск» на компьютере не синхронизирует. Но часть файлов ещё
можно вытащить, если запрашивать их **так же, как это делает сайт в браузере**,
по одному и терпеливо.

Скилл делает именно это:

- подключается к окну браузера, в котором вы вошли в свой Яндекс Диск;
- собирает список файлов в нужных папках;
- скачивает **оригиналы** по одному файлу, с паузами, чтобы Яндекс не начал
  показывать капчу;
- для каждого файла, у которого ещё живо превью, сохраняет **страховую копию
  1280 px**, чтобы у вас осталась хотя бы она, если оригинал так и не отдастся;
- недокачанное **докачивает с места обрыва** при следующих запусках;
- ведёт журнал, а после остановки продолжает с того же места.

Пароль скилл не спрашивает и не хранит: вы входите в Яндекс сами, в обычном
окне браузера. Скилл работает только с вашим аккаунтом и только на чтение:
ничего не удаляет, не перемещает и не меняет на Диске.

## Чего ожидать честно

Скилл не чинит хранилище Яндекса. Он забирает то, что Яндекс ещё отдаёт.
Каждый файл на Диске лежит на каком-то сервере хранилища. Если сервер жив,
файл скачивается за секунды. Если сервер пострадал, он молчит или обрывает
передачу.

Пример: первый проход по четырём фотопапкам одного семейного архива, октябрь
2026 года.

| Папка | Файлов | Оригинал скачан | Скачан частично | Не ответил | Есть превью 1280 |
|---|---|---|---|---|---|
| 2013 | 206 | 17 | 21 | 168 | 64 |
| 2015 | 114 | 14 | 30 | 70 | 53 |
| Images | 32 | 11 | 0 | 21 | 15 |
| Файлы в корне | 3 | 1 | 1 | 1 | 2 |
| **Итого** | **355** | **43 (12%)** | **52 (15%)** | **260 (73%)** | **134 (38%)** |

**Как читать:** «Оригинал скачан» — полный файл в исходном качестве. «Скачан
частично» — сервер начал отдавать и оборвался; кусок сохранён, следующий проход
продолжит с места обрыва. «Не ответил» — сервер молчал дольше 10 секунд, файл
отложен на повторные попытки. «Есть превью 1280» — сохранена уменьшенная копия
1280 px. Она бывает и у файлов, оригинал которых не скачался. Проценты — от
355 файлов одного аккаунта. Это ориентир, не прогноз: у вас файлы могут лежать
на других серверах, и доли выйдут другими.

Что из этого следует:

- **Пробуйте снова через день-два.** Яндекс восстанавливает хранилище, и
  серверы, которые молчат сегодня, могут ожить. Скилл помнит, что уже скачано,
  и пробует только остальное.
- **Сохраните превью сразу.** Это быстро (около 2 секунд на файл) и даёт хотя
  бы фото 1280 px, если оригинал пропал насовсем.
- **Живое превью не значит живой оригинал**, и наоборот. Превью и оригинал
  хранятся отдельно, поэтому скилл пробует оригинал у каждого файла.

| Что | Зачем | Сколько стоит |
|---|---|---|
| Компьютер на Windows, macOS или Linux | запускать скрипты | — |
| Python 3.9 или новее | на нём написан скилл | бесплатно |

## Шаг 1. Python

Проверьте, есть ли Python. Откройте терминал:

- **Windows:** нажмите `Win + R`, введите `powershell`, нажмите Enter;
- **macOS:** Программы → Утилиты → Терминал.

Введите:

```
python --version
```

На macOS введите `python3 --version`.

Если в ответ пришло `Python 3.9` или новее, переходите к шагу 2.

Если пишет «не является командой» или «not found», поставьте Python:

1. Скачайте его с [python.org/downloads](https://www.python.org/downloads/).
2. **Windows:** в первом окне установщика обязательно поставьте галочку
   **Add python.exe to PATH**, потом нажмите Install Now.
3. Закройте терминал, откройте новый и снова проверьте `python --version`.

> На macOS во всех командах ниже пишите `python3` вместо `python`.

## Шаг 2. Папка скилла и библиотеки

1. Скачайте папку `yadisk-rescue` из репозитория
   [github.com/siteactivator/free](https://github.com/siteactivator/free):
   кнопка **Code → Download ZIP**, распакуйте архив. Папку `yadisk-rescue`
   положите куда удобно, например в `C:\yadisk-rescue` или в домашнюю папку.
2. В терминале перейдите в эту папку:

   ```
   cd C:\yadisk-rescue
   ```

   (подставьте свой путь)
3. Поставьте библиотеки:

   ```
   pip install -r requirements.txt
   ```

   На macOS: `pip3 install -r requirements.txt`.

Ставятся две библиотеки: `playwright` для связи с браузером и `requests` для
скачивания. Команду `playwright install` запускать **не нужно**: скилл
работает с вашим браузером и свой не скачивает.

## Шаг 3. Куда сохранять

Выберите диск, где хватит места, и скажите скиллу:

```
python rescue.py setup --out "D:\YandexDisk_rescue"
```

На macOS, например: `python3 rescue.py setup --out ~/YandexDisk_rescue`.

Если этот шаг пропустить, файлы пойдут в папку `YandexDisk_rescue` в вашей
домашней папке. Посмотреть, сколько весят папки на Диске, можно на шаге 6. Там
же станет ясно, хватит ли места.

---

## Шаг 4. Окно браузера и вход в Яндекс

```
python start_chrome.py
```

Откроется **отдельное окно** Chrome (если Chrome нет — Яндекс Браузера или Edge)
со страницей Яндекс Диска. Это отдельный профиль: ваш обычный браузер, его
вкладки и пароли не затрагиваются, закрывать его не нужно.

В этом окне:

1. **Войдите в свой аккаунт Яндекса**, как обычно: логин, пароль, код из SMS
   или приложения. Если Яндекс покажет капчу, пройдите её руками.
2. Откройте **Диск**: должна быть видна страница с вашими папками.
3. **Не закрывайте это окно до конца работы.** Пользоваться им можно: смотреть
   папки, открывать фото. Скилл работает в фоне, вкладку не трогает. Только
   не выходите из аккаунта.

Вход запомнится. Когда в следующий раз запустите `start_chrome.py`, входить
заново не придётся.

Хотите другой браузер? Укажите путь к нему:

```
python start_chrome.py --browser "C:\Users\Имя\AppData\Local\Yandex\YandexBrowser\Application\browser.exe"
```

## Шаг 6. Список файлов и выбор папок

Скилл сначала собирает список: какие файлы, сколько весят, где фото, а где
видео. Ничего при этом не скачивается.

Указывайте папку, где лежит ваш фотоархив. Путь пишите так, как он виден на
Диске:

```
python rescue.py index --root "Фото"
```

Весь Диск целиком: `--root "/disk"`. Вложенная папка: `--root "Фото/Семья"`.

На 10 000 файлов уходит минут 5–10: Диск отдаёт список порциями по 100, и
между порциями скилл делает паузы. Потом посмотрите таблицу по папкам:

```
python rescue.py report --root "Фото"
```

```
| № | Папка | Файлов | ГБ | Из них видео | Уже скачано |
|---|---|---|---|---|---|
| 1 | 2013 | 180 | 1.10 | — | 0 |
| 2 | Отпуск 2015 | 410 | 2.60 | — | 0 |
| 3 | Телефон | 1950 | 30.40 | 300 шт., 24.80 ГБ | 0 |
```

По ней решите, что качать: всё или отдельные папки, с видео или без.

## Шаг 7. Проверить папку, ничего не скачивая

Хотите заранее понять, насколько пострадала папка?

```
python rescue.py check --root "Фото" --dirs "2013" --sample 40
```

Скилл возьмёт 40 файлов из папки (`--sample 0` — все) и для каждого покажет,
живо ли превью и на какой сервер хранилища ведёт кнопка «Скачать»:

```
/disk/Фото/2013: файлов 206, проверено 40
  превью: {'нет': 27, 'живо': 13}
  серверы хранилища (буквы в имени): {'klg': 38, 'nrg': 2}
```

**Как читать:** имя сервера — например `s466klg` или `s46nrg`, буквы в конце
обозначают группу серверов. В октябре 2026 года серверы `nrg` отдавали файлы
за секунды, а `klg` в большинстве молчали или обрывали передачу. Со временем
это может измениться.

## Шаг 8. Запуск скачивания

Одна команда делает всё по порядку:

1. сохраняет превью 1280 и оригиналы **фото** папка за папкой; внутри папки
   первыми идут файлы с живым превью;
2. потом то же для **видео**;
3. потом ещё раз пробует всё, что не ответило или оборвалось, и ждёт дольше.

Запуск в фоне. Окно терминала после этого можно закрыть:

```
python rescue.py start all --root "Фото"
```

Только некоторые папки:

```
python rescue.py start all --root "Фото" --dirs "2013" "Отпуск 2015" "Новый год"
```

Без видео:

```
python rescue.py start all --root "Фото" --no-video
```

Посмотреть, как идёт:

```
python rescue.py status
```

Остановить:

```
python rescue.py stop
```

Продолжить после остановки — **та же команда `start all ...`**. Уже скачанное
скилл не трогает и продолжает с места остановки.

Два прогона одновременно скилл не запустит и объяснит почему: запросы
удвоятся, и Яндекс быстрее начнёт показывать капчу.

**Компьютер не выключайте, в спящий режим не отправляйте, окно браузера из
шага 4 не закрывайте**, пока идёт прогон. Если что-то из этого всё же
случилось, ничего страшного: откройте окно снова (шаг 4) и запустите ту же
команду. Если вкладку Диска закрыли или перезагрузили, скилл сам подождёт до
30 минут, пока она снова появится.

---

## Шаг 9. Повторные попытки

После первого прогона часть файлов останется со статусом «не ответил» или
«частично». Через день-два повторите:

```
python rescue.py start slow --root "Фото"
```

`slow` берёт только недокачанные файлы, ждёт ответа сервера до минуты и
продолжает оборванные с места обрыва. Каждому файлу достаётся 3 попытки за
запуск. Чтобы попробовать ещё, запустите `slow` снова в другой день.

Итог по папке:

```
python rescue.py stats --root "Фото"
```

## Через Claude Code — проще всего

Если у вас есть [Claude Code](https://claude.com/claude-code), команды можно
не набирать.

1. Сделайте шаги 1 и 2: Python и папка скилла.
2. Положите папку `yadisk-rescue` в папку скиллов Claude Code:
   - **Windows:** `C:\Users\<Имя>\.claude\skills\yadisk-rescue`
   - **macOS / Linux:** `~/.claude/skills/yadisk-rescue`
3. Откройте Claude Code и напишите, например:

   > Помоги спасти фото с моего Яндекс Диска, папка «Фото»

Claude сам откроет окно браузера и попросит вас войти. Потом соберёт список и
покажет таблицу папок, спросит, что качать, запустит скачивание и будет
сообщать, как идут дела. Если появится капча, он остановится и скажет, что
делать.

## Где что лежит

Пример для `setup --out "D:\YandexDisk_rescue"` и папки «Фото» на Диске.

| Что | Где |
|---|---|
| Оригиналы, в той же структуре папок, что на Диске | `D:\YandexDisk_rescue\Фото\2013\DSC01694.JPG` |
| Страховые превью 1280 px | `D:\YandexDisk_rescue\_превью_1280\Фото\2013\DSC01694.JPG` |
| Недокачанный кусок, докачается сам | `D:\YandexDisk_rescue\Фото\2013\DSC01762.JPG.part` |
| Журнал: что с каждым файлом | `D:\YandexDisk_rescue\_rescue\rescue.log` |
| Память скилла: что скачано, что нет | `D:\YandexDisk_rescue\_rescue\state_disk_Фото.json` |
| Профиль браузера с вашим входом в Яндекс | `C:\Users\<Имя>\.yadisk-rescue\chrome-profile` |
| Настройки (куда сохранять, порт) | `C:\Users\<Имя>\.yadisk-rescue\config.json` |

**Как читать:** у оригиналов и превью стоит дата съёмки из Диска, поэтому в
проводнике и в программах для фото они сортируются по времени. Видео в папке
превью сохраняются кадром-обложкой `.jpg`.

Файлы `.part` не удаляйте, пока не закончили повторные попытки: из них скилл
продолжает докачку.

## Как читать журнал

Каждая строка — один файл:

```
2026-10-12 08:00:02 [fast 2/99] done    /disk/Фото/2013/DSC01799.JPG — 6.2 МБ за 3с, сервер s432klg
2026-10-12 08:00:19 [fast 3/99] timeout /disk/Фото/2013/DSC01800.JPG — ReadTimeout, сервер s510klg, 10с, есть 0.0 из 6.0 МБ
2026-10-12 08:29:28 [fast 44/114] partial /disk/Фото/2015/DSC03690.JPG — ChunkedEncodingError, сервер s451klg, 1с, есть 1.0 из 6.0 МБ
```

| Слово | Что значит | Что будет дальше |
|---|---|---|
| `done` | оригинал скачан целиком | ничего, файл на месте |
| `partial` | сервер начал отдавать и оборвался, кусок сохранён | `slow` докачает с места обрыва |
| `timeout` | сервер не ответил | `slow` попробует ещё и подождёт дольше |
| `error` | Диск вернул ошибку по этому файлу | повторится в следующих проходах |
| `превью …: живых 53 из 114` | сколько превью 1280 удалось сохранить в папке | — |
| `СТОП` | похоже на капчу или выход из аккаунта; скилл остановился сам | см. ниже, «Капча» |

**Как читать:** `fast` — первый проход, ждёт сервер 10 секунд; `slow` —
повторный, ждёт до минуты. `[fast 3/99]` — третий файл из 99 в очереди этой
папки.

## Сколько это займёт

Файлы идут строго по одному, с паузой 3–7 секунд после каждого скачанного.
Если сервер молчит, скилл ждёт его 10 секунд, а потом делает паузу в 1–2
секунды.

| Что | Время на файл | 1 000 файлов |
|---|---|---|
| Превью 1280 | около 2 с | около 35 минут |
| Оригинал с живого сервера | 5–10 с | 1,5–3 часа |
| Оригинал с молчащего сервера | около 12 с | около 3,5 часа |

**Как читать:** время — по первому проходу на обычном домашнем интернете.
Видео весят больше, и на исправном сервере их скачивание определяется скоростью
интернета. Архив на 10 000 файлов в первом проходе занимает около полутора
суток.

Паузы специально такие. Не уменьшайте их: при частых запросах Яндекс
показывает капчу и может на время закрыть доступ.

## Частые вопросы и ошибки

**Капча / в журнале «СТОП».**
Скилл остановился сам, чтобы не злить Яндекс. Откройте окно браузера из шага 4.
Если там капча, пройдите её руками. Если вас выкинуло из аккаунта, войдите
заново. Подождите 15–30 минут и запустите ту же команду, она продолжит с места
остановки.

**«Chrome на порту 9222 недоступен».**
Окно из шага 4 закрыто. Запустите `python start_chrome.py` снова.

**«в Chrome нет вкладки Яндекс Диска».**
В окне из шага 4 откройте `https://disk.yandex.ru/client/disk`. Адрес должен
содержать `/client/`.

**`start_chrome.py` пишет «порт не отвечает».**
Порт 9222 занят другой программой. Выберите другой:
`python rescue.py setup --port 9333`, затем `python start_chrome.py`.

**«'python' не является внутренней или внешней командой».**
Python не установлен или при установке не поставили галочку «Add python.exe to
PATH». Переустановите (шаг 1).

**Путь к папке на Диске превратился в `C:/Program Files/Git/disk/...`.**
Так терминал Git Bash портит пути, которые начинаются с `/`. Скилл это
исправляет сам. Можно писать путь и без `/disk`: `--root "Фото"`.

**Папка с пробелом или кириллицей в названии.**
Берите название в кавычки: `--dirs "Отпуск 2015"`.

**Можно ли пользоваться компьютером, пока идёт прогон?**
Да. Скилл почти не нагружает компьютер. Нельзя только закрывать окно браузера
из шага 4 и выключать компьютер.

**Общие папки (с вами поделились).**
Если папка лежит у вас в «Файлах», скилл видит её как обычную папку. Если её
нет в таблице `report`, укажите её путь прямо в `--root`.

**Нашёлся файл, которого нет в списке.**
Список собирается один раз. Если на Диске появились новые файлы или папки,
запустите `index` для той же папки ещё раз: новые добавятся, скачанное
останется отмеченным.

**Скачалось, но фото не открывается.**
Скилл сверяет размер файла с тем, что указан на Диске, и неполные файлы
оставляет `.part`. Если готовый файл всё же не открывается, значит, Диск
хранил его уже повреждённым. Откройте превью из `_превью_1280`.

**macOS: «command not found: python».**
Пишите `python3` и `pip3`.

## Безопасность и ваши данные

- **Пароль скилл не видит.** Вы входите в Яндекс сами, в окне браузера. Скилл
  пользуется уже открытой вкладкой: делает в ней те же запросы, что и сайт
  Диска, когда вы листаете папки и нажимаете «Скачать».
- **Данные не уходят никуда, кроме Яндекса.** Скилл общается только с
  `disk.yandex.ru` и серверами хранилища Яндекса. Файлы сохраняются только на
  ваш компьютер.
- **На Диске ничего не меняется.** Скилл только читает список файлов и
  скачивает их. Удаления, переименования и перемещения в нём нет.
- **Профиль браузера `~/.yadisk-rescue/chrome-profile` хранит ваш вход в
  Яндекс.** Никому его не передавайте. Когда закончите, удалите эту папку
  или просто выйдите из аккаунта в том окне.
- Пока окно из шага 4 открыто, порт отладки 9222 доступен программам на вашем
  компьютере, из интернета он не виден. Закончили — закройте окно.

## Все команды и настройки

Запускать из папки скилла. На macOS — `python3`.

| Команда | Что делает |
|---|---|
| `python start_chrome.py` | открыть окно браузера с Диском (отдельный профиль) |
| `python start_chrome.py --check` | проверить, открыто ли окно |
| `python rescue.py setup --out "ПАПКА"` | куда сохранять |
| `python rescue.py setup --port 9333` | другой порт отладки |
| `python rescue.py ping` | проверка: есть ли вкладка Диска, кто вошёл, сколько места |
| `python rescue.py index --root "Фото"` | собрать список файлов в папке |
| `python rescue.py report --root "Фото"` | таблица по подпапкам: файлов, ГБ, видео, уже скачано |
| `python rescue.py check --root "Фото" --dirs "2013"` | проверить папку без скачивания |
| `python rescue.py start all --root "Фото"` | в фоне: фото → видео → повтор недокачанного |
| `python rescue.py start fast --root "Фото"` | в фоне: только первый проход |
| `python rescue.py start slow --root "Фото"` | в фоне: только повтор недокачанного |
| `python rescue.py status` | что идёт сейчас, последние строки журнала, итоги |
| `python rescue.py stop` | остановить прогон |
| `python rescue.py stats --root "Фото"` | итог: сколько скачано, сколько осталось |

Без слова `start` команды `index`, `fast`, `slow`, `all` работают в текущем
окне терминала, пока оно открыто.

Параметры для `fast`, `slow`, `all`:

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `--root "Фото"` | `/disk` (весь Диск) | папка на Диске |
| `--dirs "2013" "Отпуск"` | все подпапки | только эти подпапки внутри `--root` |
| `--no-video` | видео качаются | пропустить видео |
| `--no-preview` | превью сохраняются | не сохранять страховые превью 1280 |
| `--pause-min 3 --pause-max 7` | 3–7 с | пауза после каждого файла. Не уменьшайте |
| `--fast-timeout 10` | 10 с | сколько первый проход ждёт ответа сервера |
| `--slow-timeout 60` | 60 с | сколько повторный проход ждёт ответа сервера |
| `--max-tries 3` | 3 | попыток на файл за один запуск `fast` или `slow` |
| `--limit 20` | без ограничения | не больше N файлов, для пробы |
